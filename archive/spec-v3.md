# 《杀戮尖塔 2》自动化决策模型技术方案 v3

> v3 修订说明：本版基于 v2（`spec-v2.md`）与相关项目深度尽调（`research/sts2-related-projects-survey.md`，其证据日志编号 [n] 下文直接引用）修订。v3 的六处变更：① **环境主路线裁定为"反编译源码 → 自研 headless Python 模拟器"，mod 降级为验证通道**（v2 默认 mod 主路线）；② §8 训练细节补 **AlphaStar/SCC/OpenAI Five 先例四件套**（KL 锚定对象、风格统计量辅助奖励、value warm-up、80/20 历史对手池）；③ §6 整局 Deep MC 主线补充 **DouZero 文献依据**；④ §3 轨道 A 引入 **CombatSolver 先例与短板清单**；⑤ M4 弱基线增加 **AgenticSTS**（LLM 对照）；⑥ M0 新增**观测完备性审计**交付物。全部变更依据见文末"附：v2 → v3 变更追踪"。

## 0. 目标定义 (Objective)

- **任务**：STS2 Ascension 10（最高进阶，Act 3 双 Boss），随机种子，单角色（首发 Ironclad），完整 run 胜率极大化。
- **难度基线**（官方 2026-05 运营数据）：A0 全体局胜率 16%，A10 约 17%（存在幸存者偏差，实际达标玩家更高）；验收以超越 A10 全体均值为及格线，以顶尖玩家水平（自述 85%）为 Stretch。
- **阶段验收**：A0 → A5 → A10 逐档爬坡，每档使用固定种子评估集（≥1000 局）。

## 1. M0 环境验证门 (Go/No-Go Gate, 1–2 周)

所有训练工作开始前，以下 7 项必须实测通过，任一失败触发对应分支：

| # | 验证项 | 通过标准 | 失败分支 |
|---|---|---|---|
| 1 | **自研模拟器**：反编译 `sts2.dll` → Python 重实现核心逻辑，完整跑通一局 | 与真实游戏对拍（同 seed 逐决策状态一致） | 阻塞，回退 mod 主路线（v2 方案） |
| 2 | **模拟器单实例吞吐** | ≥ 数百战斗/秒（参照：zhiyue/sts2-rl-agent 实测 ~1,200 战斗/秒、28,000 步/秒 [1][18]） | 重新评估采样预算；先查实现质量再查算法选型 |
| 3 | 多实例并行（8–64 进程） | 近线性扩展、无互踩 | 降低并发重估 |
| 4 | 状态深拷贝/回退延迟（模拟器内与 mod 内各测） | 单步拷贝毫秒级、无累积 GC 停顿 | **搜索轨道（§3-A）出局，直接采用轨道 B** |
| 5 | seed 控制、存档隔离、版本锁定 | 同 seed 完全可复现 | 阻塞，先修环境 |
| 6 | 状态/动作接口 | 合法动作列表完备（逐动作 `is_playable`/`has_target` 级） | 阻塞 |
| 7 | **观测完备性审计**（新增，与吞吐 spike 平级的交付物） | 历史依赖效果全量入表（本回合出牌数、遗物计数器、亡灵缚者墓地、储君辉星/铸造值、附魔等，见 §4）；审计结论经对拍验证 | 补审计后重验 |

- **环境架构（v3 主路线，裁定依据：用户裁定 + 尽调 C1 簇 [1][2]）**：
  - **训练通道 = 自研 headless 模拟器**。`sts2.dll` 无代码混淆，ILSpy 反编译可得 ~3,300 个可读 C# 文件；GDRE Tools 提取 .pck 得资源与本地化数据 [2]。卡牌/怪物/遭遇/状态/遗物等结构化 JSON（576 卡 / 111 怪 / 260 状态 / 289 遗物 / 66 事件）可从 spire-codex 直接下载 [2]，不必自写解析器。先例 `zhiyue/sts2-rl-agent` 已验证该路线吞吐与正确性可达训练标准 [1]。
  - **验证通道 = 轻量 C# 桥接 mod**（Harmony hook + TCP/JSON），仅用于把训练好的 agent 接回真实游戏做抽查验证，不承担训练采样 [1]。
  - v2 的"mod 内拦截动画 + headless 多开"方案降级为回退路线：仅当模拟器对拍无法达到状态一致性时启用。
  - **版本策略**：锁定训练版本；EA 平衡补丁后重建评估基线并重训，重训流水线为常设基础设施。模拟器与游戏版本的对应关系登记入表。
- **合规注记（用户已裁定接受风险）**：反编译 `sts2.dll` 用于个人研究用途；官方对 mod 态度为"支持使用、禁止直接收费"（STORM 报告 [6] 同源事实）；**研究成果与代码不对外分发游戏反编译内容**，模拟器以"需用户自备游戏文件自行反编译"形式处理。

## 2. 训练范式 (Learning Paradigm)

- **两阶段路线**：高水平玩家对局日志行为克隆（BC）预训练 + 接入模拟器环境的强化学习（PPO）微调。与 AlphaStar 同构：监督初始化的价值 = 强起点 + 保住人类策略多样性供 RL 探索（97.1 万 replay 的监督策略超 84% 活跃玩家 [7][10]）。
- **BC 数据来源**（无公开轨迹数据集，需自建）：mod 导出（STS2Saves / AnalyticsTelemetry / spirescope）+ A10 高手合作逐决策录制；AgenticSTS 开源的 298 局轨迹 [21] 作为格式参照与质量参差对照组，不作正式训练数据；卡牌元数据与文本/多模态嵌入（HF 六数据集包）仅用于评估器编码器初始化，**不作 BC 轨迹使用**。
- **BC 的定位**：提供"不犯低级错误"的先验与演示回放池（DQfD 式 margin 损失），不追求直接逼近高手；独立指标"BC-only A0 胜率"用于评估其质量。
- **RL 演示回放**：BC 数据常驻经验池并设 margin 损失，防止微调遗忘战斗细节。

## 3. 微观战斗：双轨赛马 (Combat Engine, Two-Track Race)

两轨共享同一状态编码器与 BC 预训练，M2 阶段按 M0-#4 结果择一推进，以"50 个 Act 1 残局基准"裁决。

### 轨道 A：策略引导 Expectimax 搜索（M0-#4 通过时启用）
- 战斗内决策权交给 Expectimax 引擎（模拟器内 Python 或 mod 内 C#，随主路线）：决策节点展开合法出牌序列，期望节点（Chance Nodes）按抽牌堆构成处理未知洗牌序，深度 3–5 步。
- 神经网络退化为 Prior-Net：仅输出候选动作先验分布用于剪枝，并充当叶节点价值截断函数。
- 通过标准：单回合搜杀均耗时 <200 ms、内存常数级无 GC 恶化、战后血量优于轨道 B。
- **先例参照（v3 新增）**：CombatSolver（社区工坊 mod，Beam Search 跨回合战斗求解器，v0.22.1 适配游戏 v0.111.0 [3]）已量产验证"根状态捕获 → 派生模拟分支搜索 → 预测/执行分离 → 状态偏离即重搜"架构 [3]；其预算预设（深搜 120 s / 12,000 节点 / 8 GB 量级 [3]）给出搜索成本的工程参照。**其公开短板即我们的反面教材清单** [4][16]：
  1. 手写评估函数对能力牌/长线收益系统性低估（作者自认"奖励函数和权重没写好"）→ 本轨道叶节点价值必须由学习到的价值函数承担，禁止纯手写权重；
  2. 长线 BOSS 战（如黑拥流少算 30+ 血）误判 → 深度截断处的价值截断质量是成败关键；
  3. 特定流派（储君印牌流）搜索空间爆炸 → 分支因子控制与状态合并需前置设计，循环检测必备。

### 轨道 B：掩码自回归策略网络（兜底主线）
- 自回归复合动作头：场景 → 主动作（出牌/技能/药水）→ 目标，逐级条件采样，**每级在 softmax 前施加动态动作掩码**（masked policy gradient；非法动作 logits 置 $-\infty$，梯度计算使用掩码后分布，避免 naive masking 的有偏梯度）。
- PPO + GAE 微调；动作空间上限参照：超过 ~1,400 时可能有数值精度问题 [2]；战斗内奖励见 §6。

### 共同约定
- 状态编码：单步 Set-Transformer（§4）。
- 环境侧硬超时：单战斗 >N 回合判负，防死锁轨迹污染训练。
- 合法动作列表由环境直接给出（接口 #6），模型不猜测合法性。

## 4. 实体 Token 编码 (Entity Tokenization)

- **类型化专用 MLP 投影 + 类型/位置嵌入**：卡牌、敌人、玩家、遗物、地图节点等异构实体分别经独立小 MLP 投影为统一维度 $d_{model}$ 的 Token；注入 `Entity_Type_Embedding` 与 `Location_Embedding`（手牌/抽牌堆/弃牌堆/消耗堆/总卡组）。卡牌语义编码用卡牌定义特征而非手牌索引（索引每回合含义漂移，是已知陷阱 [2]）。
- **单步 Set-Transformer 主干**：约 40~60 个 Entity Tokens 做 self-attention（无 1D 位置编码，天然置换不变）；全局池化若出 value head，使用 attention pooling（PMA），不用裸 sum-pooling（普适逼近反例）。
- **完备特征输入 + 历史依赖全量审计（必做清单，对接 M0-#7）**：本回合出牌数、遗物计数器、抽牌堆/弃牌堆/消耗堆构成显式编码；STS2 特有状态逐一入表——亡灵缚者墓地资源、储君辉星/铸造值、附魔状态、本回合已触发效果。种子不进状态编码（防 BC 学伪相关），保留 seed 供环境复现。
- **地图**：节点 token 额外注入邻接/层号信息（供 §7 路线图谱塔使用），不做纯集合编码。
- **接口质量原则（v3 新增，依据 NLE 复盘 [20]）**：环境接口的观测/动作参数化质量是学习成败的一级因素（NetHack 全线未通关的根因之一即接口缺陷 [19][20]）；M0-#7 审计即该原则的落地。

## 5. 多场景架构 (Multi-Scene Architecture)

- **共享底层**：通用实体 Transformer 编码器（共享卡牌、遗物、属性表征）。
- **顶层分头**：战斗头（§3）、选牌头、地图路径头、商店/营火头，按场景路由。
- **防负迁移**：按场景控制采样配比；per-head BC 损失加权；训练早期冻结主干只调头。
- **宏观头形态（选牌/路线/商店）**：非战斗动作仍保留在策略网络中（保证端到端可微与探索），但价值基线与建议由 §7 双塔评估器提供；M3 三臂消融决定最终形态。
- **分阶段训练佐证（v3 新增）**：构建期/战斗期分阶段训练在多阶段卡牌游戏有直接有效性数据（Two-Step RL，万局随机对局 78.5% 胜率 [17]），支持本方案的场景分头 + 里程碑分期结构。

## 6. 强化学习奖励函数 (Reward Function)

- **战斗内**：
  - 获胜奖励与战后剩余血量百分比挂钩（血是跨战斗核心资源）。
  - 防拖延：回合惩罚建模为 potential-based shaping（以敌方总 HP 或回合数为势函数，保证不扭曲最优策略），配合环境硬超时双保险；量级与血量奖励联合校准。
  - 监控"主动送死率"防奖励黑客。
- **宏观层**：阶梯里程碑（精英 / Act 1 / 2 / 3 通关递增正奖励，阵亡大额负奖励），量级压于终局胜利奖励，防"刷精英不推图"。
- **非战斗决策（v2 核心变更，v3 补文献依据）**：废弃 v1"纯 TD-Error 反向传播"方案。改为：
  1. **主线**：跨战斗使用**整局 Deep Monte-Carlo 回报**（无 bootstrap 偏差）。**文献依据（v3 补强）**：DouZero（ICML 2021）在斗地主上证明 MC 系在此类任务上优于 TD 系——MC 估计的收敛不受 episode 长度影响（直接逼近真实回报，γ=1），无 Q-learning 的过估计偏差，高方差由大规模并行 actor 抹平 [13][14]；该游戏同为 long horizon + sparse reward，与本任务结构同型。
  2. **辅助**：§7 双塔评估器作为 value baseline 与选牌贪心建议；
  3. **M3 消融**：纯 TD / 整局 MC / 双塔+MC 三臂对照（固定种子集），数据定胜负。
- **风格统计量辅助奖励（v3 新增，可选机制）**：仿 AlphaStar z-statistic 模式 [8]——从 BC 数据提取战斗风格统计量（如每回合出牌数分布、保血倾向），RL 阶段采样目标统计量并按执行距离给稠密辅助奖励，独立 value 函数 + GAE。用于缓解早期稀疏性；量级必须压于真实奖励，且作为 M2 消融项验证增益后决定去留（防 shaping 反噬，CombatSolver 手写权重失效是前车之鉴 [4][16]）。

## 7. 宏观评估器：卡组-地图双塔网络 (Deck-Map Dual-Tower Evaluator)

- **结构**：卡组拓扑塔（卡组+遗物实体编码，可用 HF 卡牌嵌入预热）× 路线图谱塔（后续地图节点拓扑+Boss/精英压力特征），输出当前卡组在该地图下的生存概率期望 $P(\text{win} \mid \text{deck}, \text{map})$。
- **训练方式**：self-play 终局结果自监督训练（对比学习/二元交叉熵），**不做在线 RL**——规避时序信用分配；选牌决策等价于求 $\max_{c} \; P(\text{win} \mid \text{deck} \cup \{c\}, \text{map})$ 的增量。
- **数据依赖与顺序约束**：需大规模 self-play 终局日志，故**必须先完成 §3 微观引擎（M2）再滚动收集**，M3 启用。
- **质量门槛**：Act 通关结果 ROC-AUC ≥ 0.65，低于则废除该模块（保留 MC 主线，不受影响）。

## 8. BC 到 RL 的过渡稳定性 (BC-to-RL Stability)

- **PPO + KL 退火锚定**：保留冻结的 $\pi_{BC}$ 参照；训练损失 $\mathcal{L} = \mathcal{L}_{PPO} + \mathcal{L}_{entropy} - \beta_t \cdot D_{KL}(\pi_\theta \| \pi_{BC})$，其中 $\beta_t$ 随训练**退火至 0**。损失结构与 AlphaStar/SCC 的 $L_{PPO} + L_{entropy} + L_{KL}$ 同型 [8][10]。
- **定位**：KL 只护起飞、不锁航向——中后期对 BC 的动作级 KL 仅作健康度监控（非损失项）；每 N 个迭代注入无 KL 纯 PPO 更新并以固定种子集评估，胜率不降则永久移除 KL（防止"锚定陷阱"锁死在人类亚优策略）。
- **精确超参照待办（v3 新增）**：AlphaStar 论文的 human loss 权重 w 数值与退火日程未取得（Nature 补充材料未含该数）；待读 AlphaStar Unplugged（arXiv:2308.03526）开源代码配置提取，作为 $\beta_0$ 与退火节奏的参照起点。**已独立安排执行（见工作区待办）。**
- **Value warm-up（v3 新增）**：RL 初期 value 头输出噪声大、优势估计不稳，前 50 训练步冻结策略网络只训 value 头；策略与价值共享编码器骨干 [9]。
- **防策略塌缩：80/20 历史对手池（v3 新增）**：RL 自对弈中 80% 对局打当前策略、20% 打历史版本快照（OpenAI Five 配方 [11]）。单智能体游戏无需 AlphaStar 式 league/PFSP（无对手协变问题），此轻量机制承担其防塌缩职能 [12]。
- **PBT 超参自动调优（v3 新增，可选）**：M4 爬坡阶段学习率/熵成本/LSTM unroll 可用种群训练自动演化（截断选择：底部 20% 由顶部 20% 替换 [10]），首版手动定参即可。

## 9. 环境交互与数据吞吐 (Environment Interface)

- 见 §1 M0。补充运行约定：
  - 每实例独立 profile 与存档隔离；统一 seed 管理与崩溃自动重启。
  - 吞吐参照系（v3 更新）：**主参照 = zhiyue/sts2-rl-agent 实测 ~1,200 战斗/秒、28,000 步/秒（单机 CPU，MaskablePPO 数百万 episode）[1][18]**；SCC 缩减复现（1,000 环境、30 游戏年）为"可及上限"参照 [8]；DouZero（45 actors / 4-GPU 数天达人类水平）为并行架构参照。目标采样规模同量级（10⁶ 局/日级），以 M0 实测为准外推。
  - 监控仪表盘：KL、策略熵、送死率、各场景动作分布漂移、双塔 AUC、吞吐。
