## 1. 这个项目最终应该让你获得什么

完成项目后，你应该能从一份陌生的结构化数据出发，说明怎样把它表示成模型输入，怎样设计
输出和训练目标，怎样让梯度更新参数，以及怎样用实验判断模型是否真的学到了需要的行为。
这套能力的中心是 **理解并实现 Transformer 的信息处理过程**。

具体应获得六项能力：

| 能力 | 到项目结束时，你应该能够独立做什么 |
|---|---|
| 定义学习问题 | 写出允许输入的信息、动作、奖励与评估标准，发现数据泄漏或无法表达的动作 |
| 理解神经网络学习 | 沿张量追踪一次前向、loss、反向与参数更新，区分表示问题、优化问题与数据问题 |
| 理解策略学习 | 解释策略概率、价值、优势与 PPO 更新，手算短轨迹并定位终止边界错误 |
| 实现集合注意力 | 手写 QKV、multi-head attention、ISAB、PMA，验证实体换位与 padding 的性质 |
| 实现自回归决策 | 把历史轨迹组织成条件序列，说明 causal mask、目标回报与动作标签如何配合 |
| 做可信实验 | 比较基线，隔离训练与评估，报告置信区间、效应大小、失败及结论适用范围 |

游戏成绩是实验结果；学习成果需要你留下可检查的解释和操作证据。模型胜率提高，不自动
证明你理解了 PPO；模型没有超过基线，也不自动抹去你在注意力实现和实验分析上的成果。

### 1.1 这些能力怎样迁移到别的任务

本项目给你一个观察 Transformer 内部机制的小尺度系统：卡牌与敌人提供实体 token，
战斗历史提供时间序列，合法动作提供受约束的预测空间。以后遇到文本、表格或其他决策任务，
可以重新询问同一组问题：一个 token 表示什么，哪些顺序有意义，允许看哪些信息，预测什么，
loss 落在哪里，训练数据是否支持最终主张。

这能帮助你阅读其他 Transformer 实现，但本项目不覆盖大规模语言模型的数据工程、分布式
预训练或完整对齐流程；也不把“会训练一个 STS Agent”包装成已经掌握全部深度学习。

## 2. 怎样才算“学到了”

对一个核心概念，用下面四级判断自己的掌握程度：

| 级别 | 可以做到 | 还欠缺什么 |
|---|---|---|
| L0 认识 | 听过术语，看讲解觉得合理 | 还不能据此预测结果 |
| L1 解释 | 用自己的话说出它解决什么问题 | 可能仍不会计算或定位代码 |
| L2 预测 | 面对新例子，能先写结果、shape 或变化方向 | 还需要把判断接到真实实现 |
| L3 验证与迁移 | 找到代码，验证预测，解释偏差，再处理一个没见过的变体 | 可以作为本项目的理解完成证据 |

本项目的核心链路应达到 L3。工具链、游戏细节等支撑知识达到当前任务需要的程度即可。
不要求背完每个公式；要求能说明每个符号在当前代码里是什么，并能检查自己算得是否正确。

**工程状态与理解状态分别记录。** 测试通过、文件存在、AI 解释过，都不能代替你的作答。
理解暂有缺口时，记录最关键的一个问题继续补齐，不把所有知识缺口变成新的工程阻塞条件。

## 4. 八个学习单元

这些单元沿工程依赖推进，不是八门需要先上完的课程。下面的“小实验”是学习建议；已完成的
实现优先拿来阅读和验证，不为凑练习重新搭建另一套项目。

### 单元一：环境究竟交给模型什么

**要回答的问题：** 一次 `reset → observation → decide → step`，各层分别负责什么？

C++ 维护战斗内部状态；Python 适配器只导出允许使用的观测；wrapper 整理表示；模型打分；
Agent 形成分布并选择动作；runner 组织执行。你要能逐个指出这些边界，特别是区分完整内部
状态与玩家可见观测。隐藏抽牌顺序后，不应凭观测字段齐全就断言任务完全可观测。

**从本项目学到的抽象：** 数据接口定义了模型能知道什么，动作协议定义了模型能做什么。
它们是学习问题的一部分。seed 是复现条件，不是给模型提供的线索。

**先预测，再验证：** 手牌从 `[Bash, Strike]` 换成 `[Strike, Bash]` 后，“出 Bash”的动作编号
应怎样变化？若只重排隐藏抽牌顺序，规范观测应怎样变化？若观测有五个敌人位置、动作只有
三个目标列，能否攻击第四个敌人？说明哪个接口需要修改。

代码入口：[lightspeed.py](../sts/env/lightspeed.py)、[registry.py](../sts/env/registry.py)、
[episode_runner.py](../sts/agents/episode_runner.py)。核对 [V2 观测契约](observation-contract.md) 第 8 节。

**理解证据：** 拿一个未演示过的状态，追踪某个动作编号直到环境执行；指出该过程中哪些
信息可以记录在调试文件里，却不能进入模型。可迁移到任何有权限、时间或可见性边界的数据任务。

### 单元二：从类别与数值，到可学习的向量

**要回答的问题：** 一个整数为什么有时是数值，有时只是类别？embedding 到底学了什么？

`card_id=3` 是查表的地址，不表示比 `card_id=1` 强三倍。embedding 的表项是模型参数；
HP、费用等数值经固定缩放与可训练投影进入网络。`location` 表示区域，`card_valid` 区分真实
卡与补齐行，`cost_known` 区分已知零费用与未知费用。这些字段不能因为数值都为 0 就合并。

当前 MLP 的一条张量路径是：

```text
卡牌类别 [B,80] → reshape [B,20,4] → 分字段 embedding
卡牌数值 / known / valid + 敌人特征 + 全局特征
  → 模型内投影与拼接 [B,F] → MLP
  → logits [B,31] 与 value [B]
```

这里 B 是批量，F 是拼接后的特征数。你应能解释每个轴的意义，并指出 flatten 保留了行位置，
所以当前 MLP 不天然具备集合模型的换位性质。

**小实验：** 分别修改真实零费用、未知费用和 padding；预测哪些输入张量改变。再在同一
初始化上比较缩放前后的投影输出，观察 Tanh 是否大面积接近 ±1。不要由一次探针推断全部训练效果。

代码入口：[wrappers.py](../sts/env/wrappers.py)、[MlpActorCritic](../sts/models/mlp.py)。
**理解证据：** 画出一个样本的 shape 变化；解释 wrapper 为什么没有可训练参数，模型中的
embedding 为什么能更新，以及为何 `[B,1]` 与 `[B]` 混算可能意外得到 `[B,B]`。

### 单元三：网络怎样从一个错误答案中学习

**要回答的问题：** 前向、loss、反向和优化器分别改变了什么？

在 S2 中，动作头拟合记录下来的动作，价值头拟合该条轨迹的回报。先掌握
`forward → loss → zero_grad → backward → optimizer.step`：前向计算输出，反向计算梯度，
优化器才修改参数。loss 下降应当配合参数变化、梯度有限和重载一致一起检查。

给定正确动作 y，分类损失是 `L = -log p(y)`。在合法动作集合内，softmax 交叉熵对 logits
的导数为 `p(j) - 1[j=y]`；把一个三动作例子手算一次，再用 autograd 对照。这是本报告的
教学推导练习，不要求把整个网络的梯度手工展开。

**本项目最重要的反例：** S2 标签来自随机 Agent。当模型在这 81 条样本上达到 100%，
证明的是它能拟合这批数据，不能推出新战斗更强。33 条换位增广也不等于新增 33 局独立经验。
单条轨迹回报只是一个 Monte Carlo 样本，不是该观测下期望价值的精确真值。

**小实验：** 阅读 S2 中的多数动作、仅看 mask 的捷径基线；解释为什么它们达不到门槛。
再观察只训练五步的负对照：没有 NaN 与非法动作，为什么仍不能宣布成功？

代码入口：[train_overfit](../sts/models/overfit.py)、[S2 回归](../tests/test_mlp_overfit.py)。
**理解证据：** 用自己的话区分“能表示、能拟合、能泛化、能提高游戏回报”四个命题，并为其中
任意一个命题选择合适实验。这个区分同样适用于文本分类、模仿学习与其他监督学习任务。

### 单元四：从动作概率到 PPO

**要回答的问题：** 没有专家告诉模型该出哪张牌时，已经发生的结果怎样影响下一次选择？

先分清四个对象：logits 是分数；masked softmax 产生合法分布；采样得到一个动作整数；
环境执行后返回奖励。抽样与训练必须使用同一个被 mask 后的策略，不能采样时排除非法动作，
算 log-prob 时又使用另一份分布。[L6]

例如 logits 为 `[0, ln(3), 100]`，第三项非法。先自己算合法动作的概率，再验证结果；
若把非法项先参与归一化、最后仅清零又不重新归一化，概率和会出问题。正式链路始终遵守
环境 mask；错误版本只在隔离的小例子里诊断，不作为取消项目红线的实验。

本项目当前的奖励与回报为：

```text
非终局 r_t = 0
胜利终局 R = 1 + 0.5 × 剩余HP / 最大HP
失败和任务硬超时 R = 0
G_t = 从 t 开始的奖励之和，gamma = 1
```

价值 V 是对未来回报的估计；优势用于表达一次动作相对价值基线的好坏。先从
`G_t - V_t` 理解基线，再学习 GAE 的多步估计。不要把血量系数 0.5 与 GAE 的 lambda 混为一谈。[L4]

**必须手算的练习：** 一条两步轨迹的奖励为 `[0,1.25]`，价值预测为 `[0.4,0.6]`，最后一步
真正终止。先算两个 Monte Carlo 回报，再取 gamma=1、GAE lambda=1，计算 TD 残差与优势。
把“真正终止”换成“采样批次到此结束，但战斗仍继续”，说明末尾价值项为何不同。

PPO 在同一批旧策略采样上，比较新旧策略给已选动作的概率：[L5]

```text
rho_t = exp(new_log_prob_t - old_log_prob_t)
L_clip = mean(min(rho_t × A_t,
                  clip(rho_t, 1-epsilon, 1+epsilon) × A_t))
```

理解正、负优势时两个分支怎样选择，并说明优化代码为何通常最小化 `-L_clip`。
clipping 不等于给策略变化设置了绝对保证，所以还要看 KL、熵与实际评估结果。

代码入口：[compute_gae / ppo_loss](../sts/train/ppo.py)、[数学边界测试](../tests/test_ppo_math.py)。
这些入口在本文编写时已有实现，具体训练验收仍看后续报告。

**理解证据：** 独立手算短轨迹，在代码中找到每个量；指出 rollout 如何保存原观测与原 mask；
解释任务终止为何不自举、普通批次截断为何要使用真实后继状态，以及为什么不能串入重置后新局。
面对“熵降低、回报不升”，提出至少两种可能原因和能区分它们的检查，不直接认定模型太小。

### 单元五：注意力究竟计算了什么

**要回答的问题：** 一张牌的表示怎样根据当前敌人和其他实体发生变化？

从矩阵运算理解 Q、K、V：Q 与 K 计算匹配分数，softmax 把每个 query 对各个 key 的分数
变成权重，再加权汇总 V。Q/K/V 通常都是由输入经过可训练投影得到；它们不是手写的规则标签。[L1]

```text
Q = X W_Q，K = X W_K，V = X W_V
scores = Q K^T / sqrt(d_k)
weights = softmax(scores + mask，沿 key 轴)
output = weights V
```

**小实验：** 用两个二维实体手算一次单头 attention；只修改 V，预测权重是否变化；只修改 K，
预测输出会怎样变化。随后加入一个 padding 实体，验证有效实体输出不受它的任意填充值影响。

再实现 multi-head 的拆分、各头计算、合并与输出投影，并学习 residual、LayerNorm 和逐位置
前馈层如何组成完整模块。区分实体数 N、头数 h、每头宽度 d_k 与模型宽度 d_model。

按 v5，QKV / MHA 要亲手实现，再与内置参考在相同权重、mask 与关闭 dropout 的条件下对齐。
验证前向、梯度及 mask 方向；保持手写版作为参照。代码入口在模型阶段新增，本报告不预建空文件。

**理解证据：** 不看答案写出小输入每步 shape，解释 softmax 的轴与缩放项，并定位一次
转置或 mask 广播错误。注意力图可以用于观察，但仅凭某个权重大，不能宣布它就是决策的因果解释。

### 单元六：为什么使用 Set Transformer

**要回答的问题：** 哪些顺序应该影响结果，哪些只是数据存放方式？

设 P 是实体行的排列。你需要区分：

```text
实体编码的等变性：f(PX) = P f(X)    → 换位后，每个实体的编码跟着移动
全局摘要的不变性：g(PX) = g(X)      → 同一组实体的局势摘要保持一致
```

Set Transformer 的 SAB/ISAB 提供等变的实体处理，PMA 用可学习的查询向量聚合集合。[L2]
这里 PMA 的 seed vector 是模型参数，与环境的随机 seed 完全不同。
ISAB 通过可学习的 inducing vectors 分两次注意力连接实体；你要追踪两个注意力矩阵的 shape，
理解固定 inducing 数量时为何避免完整的 N×N 交互矩阵，同时不预先宣称本项目一定因此更快或更强。

**关键架构反例：** `[Bash, Strike]` 与 `[Strike, Bash]` 可以有相同集合摘要，但“出 Bash”
对应不同动作编号。只拿摘要接固定槽位输出头会丢失这个对应关系。因此本项目的 Set/DT
动作头保留每张手牌、每个目标的编码，逐候选动作评分后再映射回环境编号；value 可以读取全局摘要。

**小实验：** 同步交换手牌与动作映射，检查相应 logits/probabilities 跟着换位，value 和结束
回合分数不变。再交换敌人、增加 padding、改变某张卡的 location，分别预测哪些性质仍成立。
location 是语义，不能把“挪到另一牌堆”当成无意义的排列。
集合编码不加入手牌槽位的位置编码；实体类型和 location 的语义表示仍然保留。

**理解证据：** 用一个未训练过的换位例子解释结构保证；说明为什么 S2 的换位样本全部学对，
仍不证明普通 flatten MLP 天然等变。这个单元的目标是学会选择适合数据结构的归纳偏置。

### 单元七：从当前集合到历史序列——Decision Transformer

**要回答的问题：** 相同的注意力机制，为什么能同时处理无序实体和有序决策历史？

本项目 B 阶段包含两层结构：内层把每个时刻的实体集合编码成状态摘要，同时保留候选动作需要
的实体编码；外层处理有时间顺序的轨迹。[L3；实体动作头扩展按 D17]

```text
内层：当前卡牌、敌人、玩家 → 集合编码 → 状态摘要 s_t + 实体编码
外层：G_0, s_0, a_0, G_1, s_1, a_1, ...
预测 a_t：可读到截至 s_t 的历史，不能读当前标签 a_t 或未来项
```

这里用 G 表示 return-to-go，以免与单步奖励 r 混淆。训练时从完整已收集轨迹计算 G；
部署评估时设置目标 G，并按已发生奖励更新 `G_next = G_current - r_t`（本项目 gamma=1）。
禁止读取这次评估战斗尚未发生的真实结局。设定更高目标回报不是性能保证，效果需要数据覆盖与实验支持。

学习顺序是：轨迹切片与标签对齐 → timestep embedding → causal mask → 只对动作预测计算交叉熵
→ rollout 推理与目标回报更新。具体用 `s_t` 位置的输出预测标签 `a_t`，该预测不能读取输入中的
`a_t` 本身。训练优化的是数据中的条件动作预测；它与 PPO 的优势加权更新不同。

**小实验：** 保持合法前缀和目标回报不变，只替换未来动作与奖励，检查当前动作预测不变。
再删除更早的历史或改变目标回报，观察预测是否变化，并区分“允许变化”与“必须变化”。

**理解证据：** 画出三个时刻的 token、可见范围与 loss 对齐位置；说明 actor 的动作头为何仍
需要当前实体，以及“能进行自回归预测”为什么不等于“模型会规划或一定超过数据生成策略”。

### 单元八：你怎样知道改进是真的

**要回答的问题：** 模型平均分更高，足以支持什么结论？还可能有什么解释？

先保留随机、规则和 MLP 基线，再比较 Set 模型。相同评估 seed 用于配对相同初始条件，
不保证不同策略之后经历完全相同的随机过程。bootstrap 应围绕配对差值并保持遭遇分层。
评估局数衡量给定策略的评估不确定性；它不能替代多个训练初始化来衡量训练波动。

务必区分两种比较：

| 比较 | 可以研究什么 | 需要控制或承认什么 |
|---|---|---|
| PPO+MLP 与 PPO+Set | 表示结构差异与性能的关系 | 同源观测、奖励、环境、预算、评估协议；参数量级可比，记录训练波动 |
| Set+PPO 与 DT | 两套学习方案在既定条件下的表现 | 在线/离线数据、训练目标、历史信息等同时有差别，不能将全部结果归因于单一架构因素 |

**小实验：** 给你一组逐局配对差值，计算均值并观察 bootstrap 区间；说明“区间跨过 0”、
“差异很小但区间不跨 0”和“只在某个遭遇改善”分别支持什么表述。

代码入口：[开发配对诊断](../sts/eval/diagnostic.py)。正式评估 seed 为 `[0,1000)`，训练与开发
诊断取互不重叠的 `>=100000` 区间；不把正式评估集用于反复调参。具体协议依 v6 §6 与 D25/D27。

**理解证据：** 写出一项结果的结论、支持证据、替代解释和适用范围。结果没有显著差异时，
能继续完成报告，而不是修改指标或挑选 seed 直到得到想要的答案。

## 5. 三种 mask 必须分开理解

| mask | 它限制什么 | 典型错误 |
|---|---|---|
| action mask | 当前状态下哪些动作可以被选 | 用下一步 mask 计算旧动作概率；采样和 loss 使用不同分布 |
| padding mask | 哪些实体或时间位置是真实数据 | 把补齐行当作实体参与 attention 或 pooling |
| causal mask | 时间序列中当前位置能看到哪些位置 | 当前动作预测读到了当前标签或未来信息 |

它们可能都最终作用于 softmax 前，但所在的张量轴与语义不同。类别为 PAD、数值为零、
非法动作和未来信息也不是同一个概念。不能只根据变量名包含 `mask` 就互换使用。

## 6. 哪些必须亲手做，哪些可以借助 AI

| 层次 | 本项目的要求 |
|---|---|
| 必须亲手推与写 | 小例子的 logits→概率→loss→梯度；短轨迹回报/GAE/PPO 分支；QKV/MHA/ISAB/PMA；DT 时间对齐与 causal mask |
| 必须能读懂、改动并验证 | MLP、embedding、rollout、masked distribution、评估与 checkpoint；每个核心张量的 shape 和来源 |
| 可以让 AI 主导实现 | 构建脚本、重复样板、图表排版、资料定位和机械迁移；你仍需检查它声称通过的证据 |
| 仅在实际阻塞时补课 | C++ 绑定内部、底层 RNG 细节、复杂 profiling、额外玩具环境；避免扩成独立主线 |

PyTorch 最低先修集中在索引、reshape、广播、矩阵乘法、autograd、Module 与优化器。
数学最低先修集中在线性代数、概率归一化、期望、对数、链式法则与均值/方差。
哪个概念卡住，就做一个能回答当前问题的小例子；MNIST、CartPole、Bandit 等不是额外的强制项目。

## 7. 每次协作怎样同时推进工程与理解

保留旧版最有用的三种思维：学生负责解释机制，工程师负责可运行与可复现，研究者负责判断证据。
它们围绕同一个任务轮换，不拆成三套独立工程。

一次学习单元建议安排为 45–90 分钟，可按实际问题缩放：

1. **你先预测。** 用 5–10 分钟写下例子的输出、shape 或变化方向；允许明确说不知道。
2. **AI 实现或运行验证。** 先做最小验证，保留输入、代码与结果，指出通过、失败和未检查部分。
3. **你解释差异。** 哪个假设对了，哪个错了，代码的哪一步决定了结果？
4. **换一个未讲过的例子。** 由你重新预测或做小改动，避免只复述刚看过的答案。
5. **留下五行记录。** 写入对应任务文档，不为每个术语建立一套新报告。

记录格式：

```text
本次问题：
我的预测及理由：
实际结果与证据位置：
修正后的解释：
迁移题结果 / 仍未理解的一点：
```

理解题先于答案，工程验收独立记录。AI 不替你写“我已经理解”，也不因为一次答错就重置全部进度。
每周选一个核心问题深入到 L3，比勾选大量术语更容易积累可迁移能力。

### 8.1 从现在开始的三个学习动作

**第一步：复盘 S2。** 阅读过拟合报告，独立回答：100% 准确率证明了什么？只看 mask 的
基线为什么达不到门槛？81 条样本为什么不是 81 局？一次 Monte Carlo 回报为什么不是精确价值？

**第二步：手算短轨迹。** 完成单元四的两步例子，再改成真正失败、任务硬超时、普通批次截断
三种边界。先写答案，再对照 `compute_gae` 和数学测试。一次只讲清楚一个边界。

**第三步：追踪一次 PPO 更新。** 用已有实现的一个小批量，把观测、mask、动作、旧/新 log-prob、
优势与 loss 对上号；解释参数更新之后，为什么原来的动作记录不变、新策略的概率却会变。
完整训练效果由 S3/S4 实验回答，不由这三个练习提前宣布通过。
