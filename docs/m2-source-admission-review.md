# M2 公开来源准入独立复审

日期：2026-09-12。任务范围：固定本地 corpus 的来源准入，不修改正式环境，不批准 M2/M3，不宣称历史规则完全认证。

## 结论与建议

应把“公开记录派生的标准规则战斗初态”和“历史原局精确重建”分成两个可独立判断的目标。项目已经明确使用前者生成新的 PPO 轨迹；每个历史 run 的完整 mod 清单不是这一目标的必要条件。它仍是历史行为等价证明的重要证据，不能因改用派生初态就声称已经取得。

建议主审在决策日志先登记 `public-derived-standard-v1`，随后同步规格与审计元数据。其含义是：从固定公开 run 的已记录内容和有证据的前缀变化派生玩家入场配置，基础初始化明确采用锁定标准规则，在锁定后端重新模拟。保留来源 build、未知历史 mod 状态、规则推导依赖和原始哈希。输出称“公开对局派生初态”，不称“历史初态完全还原”。

这不是把所有257场自动变成正式可运行场景。来源身份、字段推导、动作/内容闭包、容量、后端执行、数据分组仍须各自通过。尤其未知动态计数、未知事件前缀、药水时序、卡牌永久实例值，均不能以本策略补零或抹去。

## 建议的具体准入条件

进入派生初态清单必须全部满足：

1. 原始对象可定位到固定归档、path及SHA；角色、进阶、楼层、遭遇、build及来源关联组保留，不按胜负选择。
2. 玩家初态每项标记 `recorded`、`derived-under-locked-rules` 或 `generated-by-backend`，每条推导有输入和规则证据。源字段与推导矛盾时拒绝，不优先相信推导去修源数据。
3. 标准起始牌/基础HP/药水槽等初始化采用明确锁定规则；这一约定作为数据生成策略记录，不伪装成历史事实。拿牌/删牌/升级/HP等来源记录按已核时点保留，不能替换为随意默认值。
4. 所有影响该入口的已记录事件/商店/遗物/药水前缀可解释；缺失或有歧义导致关键玩家状态多解时整场延期。永久卡牌值及动态遗物不能猜。
5. 对明确记录的非标准卡牌修饰、未知实体、自定义挑战或与标准语义冲突的状态，拒绝或单独迁移。`basemod:card_modifiers` 非空/异常结构应有拒绝测试；全null或缺失只作为来源证据状态，不能成为历史无mod证明。
6. 环境RNG、牌序、敌人随机初始值由新环境seed按初始化策略生成；药水库存的规范槽位重排单独版本化。源seed只作关联和复现信息，不进入模型。
7. 场景中的全部实体有正式注册、可见观测和合法动作出口；可达生成、复制、分裂、状态及二次选择闭包满足容量。只支持部分卡/药水时延期整场。
8. 每个场景只有固定的来源关联组，所有楼层/副本/复跑不跨train/dev/eval；依旧使用原不可变eval_seeds.json，不根据模型成绩改分组。

第1–6条通过可以称“派生初态数据准入”；第7条是M3/M4实施依赖，第8条是数据隔离。不要把尚未实施的后端条件写成数据内容本身不可研究，更不要把数据准入写成环境验收完成。

## 最小依赖与收口建议

主审可在现有用户授权范围内先登记本策略及准确命名，并新增独立 `source_admission_policy` 与 `historical_rules_equivalence=unverified`，保留旧候选状态。重新生成清单时只推进来源策略这一维，不自动更改 backend/status、容量或正式训练状态。

若仍坚持最终目标必须是“逐场历史玩家可见初态完全真实复原”，本策略不能替代缺少的来源证明，此时应明确单独保留历史复原待审库。但该证明并不是训练锁定规则战斗策略的算法前提，不应误作为M3/M4机制实现或M5规则agent的通用阻断。

本报告不新增测试通过数、不批准任何场景正式运行、不改共享脚本与规范、不提交推送。最小下一步是主审登记策略、工具添加明确证据状态与反例拒绝，然后依据现有真实构筑选择完整支持批次并实施。
