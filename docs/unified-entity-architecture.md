# 统一实体 Set Transformer 实施契约

日期：2026-09-12。用户明确授权替代扩展主架构；此文先于统一实体模型实现登记。旧四组PPO是冻结历史实验，不能改名或沿用成绩。

## 架构配置

| 项目 | 首个工程版本 |
|---|---|
| 模型标识 | unified-entity-set-v1 |
| token类型 | CARD、ENEMY、POTION、RELIC、PLAYER_GLOBAL |
| token粒度 | 每张牌、每个实际存在的敌人、每瓶实际药水、每件遗物各一行；玩家与全局合为一行 |
| 语义编码 | 每类独立字段字典、缺失/known标记和Linear投影；公开种类采用版本化词表 |
| 共同宽度 | 64 |
| 编码模块层数 | 2，可配置，不能写死为一层 |
| 每层 | 4头自注意力，逐token前馈64→128→64，GELU，pre-LayerNorm，两个残差；dropout=0 |
| 实体类型 | 5类可学习类型embedding，加到各自投影上；不使用位置编码 |
| 关系特征 | 卡牌→敌人的公开伤害预览及known组成2维有向边；映射到4头注意力bias，随实体一起置换 |
| 全局上下文 | 对所有有效编码结果做masked mean pooling |
| 候选动作头 | 源token64＋目标token64＋上下文64＋动作类型embedding8＋源/目标存在标记2＋目标伤害边2，204→64→1，GELU |
| Critic | 上下文64→64→1，GELU |

所有类型的有效token一起进入每层注意力；不再把敌人、药水、遗物拼成大向量送到卡牌注意力之外。玩家token可以包含本人的固定状态词表，但不能包含全部其他实体的展开表。

`damage_by_target`原来用敌人槽位列定位，不能把该5列直接放进新卡牌token。适配器将它转换成对应卡牌—敌人实体之间的公开关系边；目标编号仅用于外部映射，不作为语义数值。关系边在注意力和目标动作评分中消费，保留已有信息并支持实体置换。

## 动态长度与资源

输入按实际数量构造；批内补齐至该批最大token数和候选数，使用独立entity_valid/candidate_valid/legal mask。空药水槽、空敌人位置不生成假实体；重复牌逐张保留。暂停中的公开正在结算卡作为CARD、resolving区域保留，避免从四区暂时消失时漏掉它。

不保留64张模型结构上限。第一版资源保护设单样本最多512个总token、4096个候选，批内注意力元素B×heads×N²最多8,388,608。实际张量按批最大N分配，不预铺512；这些是可版本化的资源拒绝界，不是显存峰值保证，更不是游戏规则。超过界限明确拒绝/拆分批次，绝不截掉实体。

当前80版本有限内容的采集资源方案：最多96初始牌、512个真实玩家决策，当前卡实体含resolving最多480；在466触发外部截断，465+15=480保留原子动作余量。后端累计分配上界96+512×15=7776，低于int16界；该证明绑定内容hash，不覆盖后续复制/回收/生成闭包。模型总token仍需叠加实际敌人、药水、遗物、玩家并独立校验。旧64/50扩展开发包装保留历史身份，由新统一实体采集入口替代。

## 候选动作

每个候选包含动作种类、源/目标实体引用、环境给出的legal标记和模型外route。模型只看对应实体、公开关系和动作种类；不能看到原手牌/敌人槽号、路由凭据、隐藏ID或seed。

| 动作 | 源 | 目标 | route |
|---|---|---|---|
| PLAY_TARGET | 手牌CARD | ENEMY | 当前后端0..49整数动作 |
| PLAY_SELF | 手牌CARD | 无 | 当前无目标出牌动作 |
| END_TURN | PLAYER_GLOBAL | 无 | 50 |
| POTION_TARGET | POTION | ENEMY | 当前药水整数动作 |
| POTION_SELF | POTION | 无 | 当前无目标药水动作 |
| SELECT_CARD | 候选CARD | 正在结算来源CARD（存在时） | SELECT_CARD＋当前decision_id＋candidate_index |

正常阶段由环境66位mask驱动；结构上不存在的槽位不造候选，但必须检查每个true位都有且只有一个route。选择阶段只接受环境实际暂停点及候选mask，关闭全部普通动作。将无效候选与padding先mask，再构造概率分布；无合法动作的终局只计算value，不制造一个可采样结束回合动作。

当前真实选择首先支持True Grit+的EXHAUST_ONE；跨区域/offer的候选协议可复用，其他卡和药水选择必须由其机制实现提供真实暂停点和完整来源语义。来源实体与候选不是同一用途，不能重复统计同一张持有牌。

## 恢复与实施顺序

U0：本文、跨任务接口和决策登记。U1：保留现有机制并接通True Grit+，补resolving区域。U2：统一实体编码、关系与候选接口、动态batch。U3：统一模型、置换/目标路由/mask/可见性测试。U4：模型/优化器/RNG在更新边界的checkpoint绑定与精确复测、小规模采集/反向诊断。

checkpoint绑定模型配置、词表/字段/关系/动作布局hash、实现hash、内容/环境/容量/奖励契约及后端hash。旧MLP、旧卡牌Set与统一实体模型格式不同，直接恢复必须拒绝；若以后做warm start，须显式字段映射，另立证据。首个共享checkpoint只声明模型/Adam/Torch RNG在无活动环境的更新边界恢复；完整活动环境/轨迹续跑由后续PPO集成验收，不能用权重恢复代替。

不授权新的长时间正式PPO。已有全卡机制及字段测试复用；新编码、统一注意力、实体/动作置换、动态padding、资源边界和新恢复语义必须重测。敌人/药水的新内容由另一个任务实现，本任务负责共享接口与当前内容的适配。
