# 真实卡组驱动的战斗训练计划

日期：2026-09-12。状态：P1最终卡组提取、P2开发批次、P3接口集成和本轮P4模型/轨迹迁移已完成；MLP/Set各两组GPU训练及冻结开发对照已完成。P5正式Gate与更大分布泛化仍未完成。实测见[训练报告](comparison-ppo-report.md)。

> 用户最新裁定：MLP只在[冻结环境](mlp-set-comparison-boundary.md)与Set Transformer比较，扩展环境后只推进Set。首批复用27种已验收中途卡组，最终卡组缺牌不再阻塞本轮MLP对照；[M3入口实测](real-deck-m3-report.md)记录540局集成结果。

执行依据：`spec-v6.md` 与 `decisions.md` 的“真实卡组驱动的训练起点”裁定。本计划调整初态来源要求，不重置原排期、预算、奖励和 Gate。取代旧计划中把完整历史入场还原作为训练前置条件的部分。

## 1. 目标与边界

从公开玩家记录读取完整真实卡组，保留牌的身份、重复张数和升级；其余战斗条件由版本化配置指定，交给锁定后端完成 reset。训练的是当前策略在新构建战斗中的表现。

例如：读取某个 run 的最终卡组，配上指定 HP、遗物、药水和普通精英，重新生成洗牌、怪物与开战效果。无需证明该玩家曾用这副卡组打过这个对手。

- 名称使用“真实卡组驱动的训练场景”，不称为历史战斗复盘或玩家总体真实分布。
- 最终卡组可以直接使用，标记为最终卡组；不得冒充某个早期楼层的历史卡组。
- 已经可靠提取的中途卡组也可以使用，不再为凑足中途快照扩建历史事件重建器。
- PPO 的轨迹由当前策略在模拟器中采集，公开玩家动作不作为 PPO 的 on-policy 批次。
- 当前仍是 STS1 Ironclad 独立 battle，地图、商店、事件和完整 RunEnv 不进入实施范围。

## 2. 数据字段的责任划分

| 字段 | 取得方式 | 必须检查 |
|---|---|---|
| 卡牌身份、数量、升级 | 公开记录 | 完整多重集、可解析、无静默删牌或降级 |
| 卡牌永久实例值 | 来源明确值，或明确登记的标准化策略 | 不把未知历史值默认为已知；首批优先不依赖此类值的卡组 |
| 来源、原文件哈希、run 关联组、快照类型 | 数据提取器 | 可追溯、去重、按来源隔离 |
| 当前/最大 HP、金币及其他 reset 必需上下文 | 训练配置 | 数值合法、规则语义明确，不标为历史实录 |
| 遗物及计数、药水及槽位 | 训练配置 | 已支持机制、明确初始计数、容量合法 |
| 怪物、进阶、幕/层等生成上下文 | 训练配置 | 与后端生成规则相容，完整保存配置 |
| 火精英标志 | 训练配置 | 首批明确 false，不索要原局火精英证明 |
| 洗牌、怪物随机数、内部初始化状态 | 后端与独立环境 seed | 可复现，隐藏信息不进模型 |

来源不提供遗物或药水历史，不影响卡组资格。遗物和药水仍是训练环境的组成部分：可以明确配置空药水，也可以配置已支持药水和遗物；这属于实验条件，不是假称玩家当时没有它们。

不支持的卡组保存并给出具体原因。首批按完整卡组筛选；若可用构筑太少，按实际卡组缺口优先补机制，不通过删牌凑数量。任意额外合成或删改卡组须另行标记，不能混入原始真实卡组统计。

## 3. 复用成果与停止的前置工作

复用现有固定来源缓存、来源哈希与 run 关联分组、卡牌机制审计、中央内容契约、PublicBattleEnv 的原生初始化、完整语义观测、66 位动作协议，以及随机和规则 Agent。

既有 99 场历史派生场景及其报告保留原身份。它们的运行记录不等于本计划已经实施，也不能直接替代新场景集的验证。

以下工作退出训练关键路径：逐事件/商店前缀补齐、历史药水库存追踪、历史遗物计数恢复、逐场火精英身份举证、开战后快照内部状态恢复，以及依赖这些条件的三方分布汇总返工。已有审计缺陷和失败报告保留，不标为已修复。

后端机制错误、模型遗漏可见信息、动作无出口、容量越界仍须修复；这些会影响实际训练，不能随来源要求放宽而跳过。

## 4. 实施顺序与交付

以下 P1–P5 是本次路线调整的执行步骤，不替换原 M 编号。

### P1：读取真实卡组库（对应 M2 数据部分）

- 先使用已经下载并固定哈希的公开语料，直接提取完整卡组字段；不重新进行大规模联网搜集。
- 输出版本化卡组清单、原始来源索引、拒绝原因及覆盖报告。建议交付名为 `real-deck-manifest.json` 与 `real-deck-data-report.md`，实施时生成，不先建空文件。
- 保留快照类型、来源 run、完整卡组内容哈希和原始数据哈希。来源牌名映射到当前标准规则卡牌时保留映射依据，不声称历史所有 mod 行为一致。
- 报告独立 run 数、不同完整卡组数、不同于基础卡组的构筑数、卡牌/升级覆盖、卡组大小分布和不支持内容。不得只按场景乘 seed 后的数量宣传规模。
- 优先使用现有可信分组；跨来源发现同一 run 的重复记录时合并关联组。来源身份不明的重复候选保守归组或隔离。

验收：抽查原记录与输出卡组逐张一致；重复牌、升级、不支持内容有针对性测试；输出全部候选的通过/拒绝统计。最终可用数量由实际提取结果确定，不沿用旧 99/19 数字。

### P2：锁定战斗配置与新准入协议（对应 M2 契约部分）

- 登记独立来源策略 `real-deck-configured-battle-v1`，旧 `public-derived-standard-v1` 保持历史含义。
- 第一批限定已有支持的普通怪与非火精英。怪物可以与来源历史不同；训练配置明确 HP、遗物、药水、进阶及所有生成上下文。
- 先设一个明确的开发配置，再增加少量可解释的条件组合。准确数值、采样权重和名单在实施时写入配置文件并冻结，不能留隐式默认值。
- 先按来源 run 关联组划分训练、开发、保留评估，再扩展怪物/HP/药水组合；同一来源所有快照和复跑不跨组。
- 主评估衡量未见来源卡组在同一配置分布下的表现；未见怪物组合或更难条件另列泛化测试，不混进主分数。
- 相同卡组若来自不同独立 run，报告跨分区内容重叠；若声称未见卡组泛化，还须按完整卡组内容关联隔离。

验收：配置完整、划分无来源泄漏、采样规则可复现；在采样前固定权重，避免多快照 run 或大量基础卡组不受控地主导训练。预先看过或用于诊断的场景不冒称未触碰的保留评估集。

### P3：构建 reset 并接通两条基线（对应 M3 环境与 M4/M5）

- 复用原生 pre-init 初始化代码，为新来源策略建立正式入口与校验。不得用 `diagnostic=True` 绕过旧准入后直接用于正式训练。
- 输入为真实卡组和明确配置；后端生成手牌、洗牌、怪物及内部状态，开战效果只结算一次。
- 首批非火精英由配置明确设置 false。火精英强化接入和测试另排后续批次，不阻塞首批普通精英。
- 在新清单上运行随机/规则 Agent：覆盖每种配置及内容边界，检查合法动作、正常胜负、异常与外部截断；对代表性场景验证同 seed 可复现。
- 新来源策略及配置哈希进入运行元数据。观测/动作语义没变化时复用现有协议；确需改变时单独升版本，不用数据来源变化掩盖模型接口变化。

验收：新正式入口实际 reset/step 可运行；输出逐场结果与异常原因；相关旧范围回归通过。全胜、规则优于随机不是 reset 正确性的替代证据。

### P4：迁移张量、模型头和训练轨迹（完成 M3 学习管线缺口）

- 将 public 语义观测接入 MLP/Set 所需编码，覆盖完整牌堆、升级/动态可见牌值、敌人、遗物和药水；区分 padding 与真实实体。
- 迁移动作头、mask、rollout、最终观测、自举和 checkpoint 元数据。旧 31 动作 checkpoint 不直接当作新环境可继续训练的权重。
- 验证模型实际能区分影响决策的状态；不得只验证张量 shape，也不得遗漏可见信息后靠继续训练补救。
- 先运行 MLP-PPO 短诊断，核查实际采样步数、异常、曲线、合法动作和保存/恢复；通过后按原学习计划进入 Set 编码与对照。单次短训不证明算法稳定收益。

验收：编码与动作端到端一致；终止/截断和恢复检查通过；诊断报告区分工程成功与策略收益。每批数据变化不必重做“证明 PPO 正确”，接口或分布发生实质变化时进行对应的集成/学习诊断。

### P5：正式配对评估与学习复盘（对应 M6–M8）

- 规则/随机先按既有 Gate 2 协议评估；后续 MLP/Set 在相同场景、配置、奖励、gamma 和配对环境 seed 下比较。
- `eval_seeds.json` 保持不可变；训练 seed ≥100000，正式评估按已有 [0,1000) 约束。新场景清单、划分和采样映射单独版本化。
- 报告综合回报、胜率、出口血量、分桶结果、异常和截断；统计处理同一 run 多场景相关性，不把复跑当作独立玩家。
- 评估前冻结协议与配置；未通过时按 `spec-v6.md` §10 执行，不临时改变分布或删掉困难组以过 Gate。
- 学习验收仍单列：用户解释真实卡组与历史复盘的区别、reset 随机性、mask、配对比较和泛化边界。

## 5. 交付与审核方式

每个步骤交付可复现命令、实际输入/配置哈希、产物、针对性验证结果和未完成项。主审核对真实输入与端到端运行，不只审自造 schema 单测。

P1 与 P2 的框架可同时准备；P2 数值与划分冻结须消费 P1 实际数据，P3 须消费已冻结契约。模型迁移可基于现有语义接口准备，训练运行须等待 P3。避免三个任务各自猜测对方输出格式、反复重建报告。

用户分发任务时按此依赖给提示词。计划形成后的本轮已按用户“开始”执行 P1，未创建新任务或启动训练。
