# M3逐牌编码与MLP/Set PPO实施记录

日期：2026-09-12。状态：环境与模型接口已实现，训练结果以运行目录和本文后续实测记录为准。

## 已确认的执行范围

用户确认本轮完成MLP-PPO与Set-PPO，顺序推进，每种模型两次独立训练；比较相同环境交互步数，训练收益须相对初始策略有可重复提升，Set不必超过MLP。正式训练、评估和可能的正式重跑累计不超过1800秒。开发、接口测试和有上限的资源预检不计入正式预算。

模型架构、容量与采集协议现已落地。旧comparison-battle-v1的卡组、遭遇、条件保持不变；增加用户批准的容量外部截断后，运行身份为`comparison-battle-v2`，终止协议为`battle-capacity-collection-v1`。旧540局集成不是该新协议的训练证据。

## 卡牌位置与容量

- 冻结27种卡组的初始张数为9–14，最大14。
- 双方使用64个逐牌实体位置，重复牌分别编码，不做数量聚合。有效实体不足时padding并设置有效mask。
- 手牌保持实际顺序放在最前面，随后按区域和完整公开字段确定排序放抽牌堆、弃牌堆、消耗堆。区域one-hot区分牌区。未使用位置编码、来源seed、内部实例ID或真实抽牌顺序。
- 10个手牌动作槽由前部实际手牌路由；手牌不足10时，对应其他出牌槽由环境合法mask关闭，不能把后续非手牌当作可出牌对象。
- 一个动作结算前若仍在采集，实体数至多56；单动作保留8张增长余量，因此结算后至多64。达到57时外部截断，完整最终观测用于自举，自然胜负优先。
- 保留512动作预算；容量和动作预算任一触发均是外部截断，不是游戏失败。源码实际增长若超过8或实体超64直接报告异常，不截掉实体后继续训练。

8张余量只适用于冻结范围：Wild Strike/Reckless Charge/Immolate一次各生成1张，Power Through一次生成2张；三哨卫按外侧Bolt/中间Beam初始化，再分别交替，A20一次最多两个Bolt共6张。其他冻结卡牌、两种普通遭遇、Nob/Lagavulin及两套配置的遗物药水无额外加牌链。依据锁定后端`BattleContext.cpp:1068/1127/1187/1407`、`MonsterSpecific.cpp:1037/1043/2644`。扩展内容时不能沿用8的证明。

压力探针：`python scripts/diagnose-comparison-capacity.py`。Power Through卡组对三哨卫只防守，20个开发seed中10局触发容量截断，最大实体数59、最大单步净增长6。证据在`reference/comparison-capacity-probe.json`；这是刻意维持战斗的压力样本，不是训练截断率估计。

## 双方共同输入

输入包含`ids[64]`、`cards[64,29]`、`valid[64]`、`global[1246]`、`mask[66]`。

每张牌保留身份、升级、基础/当前费用与已知标志、基础及当前格挡、伤害、逐目标伤害、magic、攻击次数、牌类型、牌区、目标类别、全体攻击、耗尽、虚无、暂时免费及保留属性。名字与稳定ID一致性检查通过后用ID表达身份，不重复把名字编码为文本。

全局向量完整保留玩家公开数值和状态，5行敌人身份/数值/意图/公开历史/状态，3行药水身份/效力/目标类别/存在性，遗物身份/计数是否已知及值、药水实际容量。状态的存在标志与数值分别编码；未知字段/类别明确拒绝，不静默映射为0。

枚举及其顺序冻结在`sts/env/comparison-contract.json`。数值只按固定尺度缩放，不裁剪，不从公开字段之外推断隐藏状态。双方使用完全相同的`encode`函数。

## 已实现架构

| 部件 | MLP | Set Transformer |
|---|---|---|
| 卡牌身份嵌入 | 8维 | 同左 |
| 每张卡牌投影 | 29数值/类别特征＋8维嵌入→32维，Tanh | 同左 |
| 全局投影 | 1246→64，Tanh | 同左 |
| 编码器 | 展平64×32，与64维全局拼接→128→128，Tanh | 1个SAB，32维/4头；1个PMA，1个可学习查询；与64维全局拼接→128→128 |
| 注意力内部 | 无 | 手写Q/K/V、softmax、padding mask、残差、LayerNorm、32→64→32前馈；无dropout/位置编码 |
| 手牌Actor | 128维状态与每张32维牌表示→64→5，共享评分器，路由10槽 | 同结构，使用注意力后的逐牌表示 |
| 其他Actor | 128→16：结束回合及15个药水动作 | 同左 |
| Critic | 128→1 | 同左 |
| 总参数 | 381150 | 140222 |

两模型共享各自内部的Actor/Critic编码器，但模型之间不共享训练权重。允许参数量不同，以相同交互步数为主对照，并报告耗时与内存。Set这里只对卡牌实体做集合注意力；玩家、敌人、遗物和药水通过双方相同的固定布局全局编码进入，不能称为所有实体的统一token注意力。

## PPO、恢复与预算

复用已有通过验证的GAE和PPO损失函数，新采集器使用8环境×64步=512 transition/轮，4个minibatch、4个epoch。公共设置：lr=0.00025线性退火、Adam eps=0.00001、gamma=1、lambda=0.95、clip=0.2、entropy=0.01、value=0.5、梯度裁剪0.5。

采集保存原动作mask、旧logprob/value、真实奖励、terminated/truncated、reset前最终观测。真终止不自举；外部截断自举但GAE不跨reset。截断episode的完整回报为未知，单独记录observed_partial_reward，不把它作为失败0纳入平均完整回报。

checkpoint包含模型、优化器、场景/动作/洗牌/Torch/CUDA RNG、环境seed和当前局已执行动作。通过重放恢复活动环境；记录源码、后端与配置指纹。正常轮边界支持精确恢复；采集/更新中途的失败快照只用于诊断，不能假装是完整轮边界继续恢复。

`scripts/run-comparison-ppo.py preflight`每种模型先4轮测时，再验证一次保存/恢复后的下一轮更新完全一致；每种模型预检有180秒上限。随后按较慢者测时及35%余量确定相同正式步数，四组训练估算合计至多1100秒，余量留给评估、保存和波动。正式运行设1790秒活动截止，预留10秒写报告；不足时明确记budget_exhausted，不减少组数或只保留最好结果。

## 开发评估与验收

评估使用冻结开发侧12个组内卡组条目×2条件×5遭遇=120场，环境seed从970000开始。每组训练前后使用相同场景/seed，采用贪心策略。来源10个run为bootstrap单位，先组内平均再计算5000次bootstrap的95%区间。

如有容量或动作预算截断，完整回报未知，按[0,1.5]传播到差值上下界，不补失败0，不只挑双方都完成的容易样本。学习验收为同一架构两组各自最终减初始的组级区间下界均大于0。MLP/Set最终结果在相同场景上另外配对报告。该CI不覆盖两个训练初始化之外的随机性；开发来源已接触过，不宣称未见构筑泛化或正式Gate。

诊断修正最多2轮且不得突破共同时间预算；无明确假设不自动调参。本轮尚未进入正式运行前，不写训练通过结论。
