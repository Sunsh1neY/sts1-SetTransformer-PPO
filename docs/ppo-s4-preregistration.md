# D25 S4 多初始化开发诊断预登记

登记日期：2026-09-11。依据：spec-v6.md §9.1、D25/D27。用户要求先让电脑运行测试。
本登记在三组训练启动前写入；本轮仅测试 battle/minimal-v1，不扩建环境。

## 固定设计

- 三组均从新权重开始，不使用 S3 checkpoint，不按结果换 seed 或延长预算。
- 共用 configs/ppo-minimal.yaml 的算法参数，每组 262144 transition、256 轮、8 环境×128 步。
- 每组 CPU 单线程；可并行执行三个独立进程。
- 训练环境 seed 范围均为 [1000000,2000000)，按既有收集器顺序分配；不同策略消耗的局数可能不同。本实验改变模型、动作采样和 minibatch 洗牌 RNG，不声称单独隔离了模型初始化的影响。
- 环境为锁定 C++ 后端的 Jaw Worm、Cultist、Two Louse；训练混合三种遭遇，开发评估逐遭遇分桶。
- 奖励 battle_reward_v1，gamma=1、alpha_hp=0.5、beta=0；其余契约沿用 v6。

## 评估与报告口径

- 共用开发环境 seed 900000..900299，三遭遇各 100 局；agent seed 从 950000 开始；bootstrap seed=960000，重复 10000 次，按遭遇分层配对重采样。
- 模型和均匀合法随机均按掩码后概率抽样；使用最终第 256 轮权重，不挑最好 checkpoint。
- 正式 eval_seeds.json 仅记录哈希，不参与本轮开发评估或调参。
- 逐组报告平均回报差、paired bootstrap 95% CI、胜率、HP、遭遇分桶、训练步数、非法动作、超时、非有限异常、末轮 EV 及训练曲线。所有失败和未完成组均保留。
- 每组最低改进门槛为总体回报差 CI 下界 > 0；仅三组都满足时，称本次三组均重复观察到改进。任一组不满足，报告未全部达到门槛并诊断，不以合并平均掩盖。
- 三个模型的局级 CI 不代表跨初始化总体 CI；三组证据有限，不宣称普遍稳定、最优或 Gate 3 通过。
- 运行入口复用 scripts/run-ppo-minimal.py，其自动生成的 experiment/note 仍为历史 S3 字样；各运行所属 S4 以本登记、对应配置与启动清单为准，不把自动 note 当作阶段完成裁定。
- 保存现有入口生成的源码归档、配置、元数据、优化器/RNG checkpoint 和失败文件；异常后先核对最近完整快照与源码兼容，禁止静默从头替换。
