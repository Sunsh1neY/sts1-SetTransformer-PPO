## 1. 本周要交付什么、学会什么

工程目标：在正式 C++ 战斗环境之上，完成统一观测 dict、FlattenWrapper、TokenWrapper 和动作掩码使用闭环，并形成 Gate 1 验收记录。

学习目标：你能拿一份真实战斗观测，解释它如何变成两种模型输入，指出哪些信息可以使用、哪些位置只是补齐、模型输出如何对应回牌和目标，并用一个反例验证设计。

本周最值得学的三件事：

1. **表示决定模型能知道什么。** 会区分模拟器内部状态、玩家可见观测、数值编码与可训练表示。
2. **集合里的实体与动作编号如何对应。** 会解释“牌的特征不含槽位号”，为什么仍然要保留每张牌与输出动作的位置关系。
3. **用实验检查约定。** 能先预测换位、改变隐藏信息或屏蔽动作后的结果，再用测试判断，而不是只看测试总数。

工程完成与理解完成分别记录。测试全绿不自动代表你已经掌握；学习练习也不替代工程验收。

### T1：先说清每个数是什么意思

目标：建立后续 agent 能照着实现的输入输出契约。

做法：agent 先阅读 C++ 适配补丁中的 `HAND_FEATURES`、`ENEMY_FEATURES`、`GLOBAL_FEATURES` 与当前测试，运行一个训练范围 seed 的真实样例。列出字段名称、含义、类型、可见性依据、类别/连续值、缺失与无效值处理。沿用既有证据；未核实的游戏可见性写 `[未核实]`，不得用“代码能读到”代替来源。

当前物理布局为手牌 `[10, 3]`、敌人 `[5, 12]`、抽牌/弃牌堆各 `[3]`、全局 `[11]`，相应实体 mask 长度为 10、5，动作 mask 长度为 31。牌堆字段是 D22 在 T3 完整性审计后补入；这些都是 C++ 缓冲布局，不直接等于最终模型维度。

开工时必须处理三个具体接口问题：

- C++ 预留 5 个敌人位置，动作却按 `slot * 3 + target` 编码。当前最多双敌人，不能据预留容量擅自把动作扩为 51 个；写清 wrapper 保留哪些位置、如何对应目标索引。
- `enemy_mask=false` 的位置可能仍有数值。明确死亡/无效实体与补齐位置的处理，两个 wrapper 必须一致，不能让 MLP 读到另一条路径已屏蔽的残留信息。
- 规格 §4.2 写 TokenWrapper 输出 `[n_token, d_model]`，§3 又规定类型专用可训练投影。明确原始实体特征到模型投影的边界；本周优先完成确定性数据准备，模型阶段接可训练投影。若实际接口与规格表述不同，先在决策日志登记阶段性约定并同步规格，不能悄悄用随机投影冒充已实现的模型编码器。

你来做：从样例任选“玩家 Weak、卡牌 ID、seed”解释其去向；画出或口述 `内部状态 → 可见观测 → wrapper → 后续模型`。

完成标准：agent 能依据字段表实现，不需要猜测 dtype、mask 中 True 的含义、实体顺序或终局返回值；你能说明至少一个信息泄漏的反例。

### T2：给正式后端一个统一的数据入口

目标：后面的模型只依赖稳定的 Python 接口。

做法：

1. 在现有包中增加必要的薄包装，把 C++ 观测转成含 `hand/enemies/global/hand_mask/enemy_mask/action_mask` 的 dict；读取字段常量校验布局，不能随意依赖上游枚举编号的大小。
2. 只按白名单转换观测；`info` 保留调试与复现用途。明确 reset 与 step 返回约定，保持奖励、终止标志和合法 mask 的含义。
3. 保留 C++ 给出的实体与目标对应关系；如需移除补齐行，要有明确映射。不能按牌名排序后仍沿用原动作编号。
4. 验证观测快照独立性：保存时刻 t 的输入，再 step 到 t+1，旧输入不能被复用缓冲区悄悄改写。允许为此作必要的小数组拷贝。

你来做：沿一次真实 step 找到“输入动作、输出观测、奖励、终止标志”各在哪一行转换；说出哪个值会送入模型、哪个只会落盘。

完成标准：从项目包入口可运行三种遭遇；dict 的字段、dtype、shape 可检查；旧观测不变；结束后不再采样或 step；改变包装方式不改变环境奖励和轨迹。

### T3：实现两种输入，保留相同信息

目标：为将来的 MLP 与 Set Transformer 提供公平的表示对照。

做法：按 T1 契约实现 `sts/env/wrappers.py` 中的两种 wrapper，共用字段选择、类别映射和连续值处理。

- FlattenWrapper：按记录好的顺序补齐并展开，能解释每段向量来自哪个字段；不能只丢掉无效位置却保留其残留值。
- TokenWrapper：保留每张牌、每个敌人的独立实体特征与 mask，明确玩家/全局信息如何传递；本周不写 attention 网络。
- 卡牌 ID、怪物 ID、意图类别作为类别处理，选定一种明确的类别映射方式；不要把“ID 200 比 ID 20 大十倍”当成语义。若采用 one-hot 或后续 embedding，标明所在层与维度。
- 连续值若缩放，两个 wrapper 使用相同规则并记录系数；不要用固定评估集拟合归一化统计。

你来做的核心练习：构造同一局势下 `[Bash, Strike]` 与 `[Strike, Bash]` 两份输入，先写下 token 行、扁平向量、动作编号、合法 mask 分别应该怎样变化，再让 agent 执行测试。接着讨论：如果只把所有牌汇总成一个不随换位变化的摘要，怎样知道“打 Bash”该输出哪个编号？

完成标准：

- 两条路径可逐字段追溯到同一份 dict，语义与 mask 一致；“长度一样”不能作为同源证据。
- 手牌或有效目标换位时，实体特征与相应动作映射一致变化。无目标卡仍只对应目标 0，不能像攻击卡那样盲目交换目标列。
- 改变无效位置的填充值不影响规范化后的有效输入；槽位号不进入 token 特征。
- 固定可见观测，仅改变附带的 seed/RNG 等调试数据，编码不变。另检查后端白名单；只修改 info 的测试不足以证明 C++ 从未泄漏隐藏值。
- 模型的动作概率等变性与价值不变性留到模型阶段测试，本周不要把 wrapper 换位测试宣称为整个 Set Transformer 已通过验收。

### T4：让“选动作”与“动作合法”正确连接

目标：理解动作 mask 与实体 mask 的不同职责，并验证合法动作闭环。

做法：正式随机策略仅从环境提供的合法动作中采样，分别经过两种 wrapper 跑到终局，记录实际发送给环境的动作。wrapper 不重算合法性。

另用很小的 NumPy 例子演示 masked softmax：先把非法动作的 logit 屏蔽，再在合法集合上归一化。保存后续策略计算 log-prob、熵与梯度必须使用同一掩码后分布的约定；自动微分验证在接入 PyTorch 时落实。

你来做：给三个候选动作设置 logits 为 `[0, ln(2), ln(3)]`、合法 mask 为 `[True, False, True]`。手算屏蔽后的概率、两项合法概率的比值，并说明为什么“先 softmax 再清零却不重新归一化”不是概率分布。先保留你的预测，再运行代码。

完成标准：合法概率和为 1，非法概率为 0；只有一个合法动作时概率为 1；非终局若全非法应显式报错；终局全 False 是正常状态，跳过采样，不能人为开放结束回合来掩盖问题。无目标卡去重、攻击目标与动作 30 的含义保持原约定。

### T5：测完整路径，定位实际开销

目标：知道现在交付的环境是否可靠、是否足够快，并能解释测量口径。

做法：提供一个可重复执行的验收入口。三遭遇配置明确，开发与压力测试使用 seed ≥ 100000，随机策略也固定独立 RNG。按相同 seed 与动作策略比较原接口、dict、FlattenWrapper、TokenWrapper 四条路径。

建议将 10000 场验收 seed 在三种遭遇间明确分配，两条 wrapper 路径各跑相同的整套配置。汇总每条路径的场数、步数、异常数、非法动作数、超时数及比例、累计奖励检查结果；按遭遇保留分项，避免总体数字掩盖某一条路径的问题。

确定性验证至少沿用 Week 3 的 60 场覆盖量，在相同 seed、相同动作序列下重跑，逐步比较观测、mask、奖励和终止标志。需要“逐字节相同”时固定序列化字段顺序、dtype 和字节序；时间戳等运行元数据单独记录。

性能测量分别报告单核原接口与完整 wrapper 路径。限制相关库线程数为 1，预热后重复测量，例如 3 次，报告步数/耗时、各次结果与中位数；说明是否包含 reset、观测转换与动作采样，避免逐步打印。完整路径以 ≥ 2000 步/秒为本周交付目标。

只有低于目标或出现明确热点才优化：先分段计时，定位重复转换、无用大拷贝或分配，再改一处并复测。保留 T2 要求的快照独立性，不为“去拷贝”破坏轨迹数据。

你来做：测量前预测最慢的一段，测量后解释预测与结果为何一致或不同；说明“原接口每秒十万步”为什么不能证明模型训练循环也有同样吞吐。

完成标准：稳定性与确定性结果可重跑，奖励仍满足 D18/D20，单核吞吐达到目标。硬超时应单独列明，出现后先查明原因；“极低”沿用 §5.1 的表述，不能临场调整定义使结果通过。

每个 run 按 §8.1 记录 git commit、完整配置、随机种子、固定评估集 sha256。若基于未提交改动运行，还要保存能复现该代码状态的差异；只记基础 commit 不够。最终稳定性验收使用确定的代码版本。
