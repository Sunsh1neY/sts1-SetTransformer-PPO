## 2. 划分与结论范围

当前来源分组为65个run训练侧、10个run开发侧；分别80和12个组内卡组条目。来源run不跨侧，但有4种相同卡组内容出现在两侧，不能声称这是严格的“未见卡组”泛化测试。

这些来源已参与此前开发和本轮集成，不是未触碰的保留评估集。正式训练前另行冻结配对评估清单、统计方法及可声称的结论；可以检验固定任务中新随机性的表现，不能通过改名制造新卡组泛化证据。eval_seeds.json保持不变，调试不用其中的seed。

条件二同时改变HP和装备，是一个组合条件，不用于单独归因某一遗物、药水或HP的因果效应。

## 3. M3 接下来只补模型与采集接口

1. 已进入：新真实卡组策略的正式reset入口、批次校验、分组采样与两条基线集成。
2. 下一项：冻结双方共享的数值特征字典、归一化和容量布局。手牌动作仍按实际槽位对应，语义token不添加槽位编号；抽牌堆等不暴露真实顺序。
3. MLP采用不丢公开字段的固定布局基线；Set采用实体token编码与相应mask。先做最大配置的内存/吞吐测量，再锁隐藏宽度与批量。不得仅为方便MLP删掉后端可见状态；若采用无损聚合，必须证明可恢复所有任务相关公开字段并让双方使用等价信息。
4. 接入66动作head、rollout、截断自举、保存恢复，进行MLP短诊断，再进行同环境Set训练与配对比较。
5. 训练步数预算、优化器/PPO公共设置和调参机会按共同协议锁定；记录参数量、耗时和显存/内存，不能把不同采样预算误说成纯架构收益。

本次冻结环境，不预先声称模型容量设计、Set实现、PPO短训或正式Gate已经完成。

## 4. 对照完成后的扩展规则

- MLP在comparison-battle-v1完成对照后冻结代码版本、配置、数据、checkpoint和报告，不继续扩卡、改动作头或迁移新状态字段。
- Set Transformer先在同一个comparison-battle-v1完成对照，然后进入后续扩展环境。
- 扩展后的Set结果单独报告；不能和旧环境MLP分数直接并列后宣称架构更优。
- 环境机制修复若改变转移或奖励，登记新版本，评估对原结论的影响；这是修正实验错误，不是重新开启MLP无期限扩展。
- 原comparison-battle-v1保留可复现版本；新增白名单不得静默改变冻结环境的含义。

最终卡组库146副仍作为Set后续扩展输入，不再成为本轮MLP对照的前置要求。
