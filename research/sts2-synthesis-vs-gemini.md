## 0. 30 秒结论

两份报告**在同一处判断失误、在同一个痛点上撞车、在解决方案上互补**：

- **撞车点（最高价值共识）**：甲认定"非战斗决策纯靠 TD 反传"是最大学术风险（梯度信号稀薄），乙更激进，直接判死刑（"极易梯度消失或噪声淹没，无法有效指导 Act 1 选牌"）。两报独立得出同一结论，这一条从"风险提示"升级为"已定案的设计缺陷"，必须改。
- **甲对乙的关键纠错**：乙全文沿袭 "A20" 目标且未察觉其不存在——**STS2 进阶只有 10 级，最高难度 A10**（官方 Neowsletter + 双指南交叉证实，甲报 [2][3][4]）。乙的验收指标（"100 万局完整 A20 对局"）全部建立在错误目标上。
- **乙对甲的关键补强**：甲完全没覆盖**搜索路线**（Expectimax MCTS 算杀）。乙指出的"微观计算脆弱性"（神经网络在算杀/出牌顺序上的精度失误会连锁崩溃）是真实的、甲承认的盲区。乙的第一个工程验证步骤（C# 状态深拷贝 Benchmark）应并入甲的 M0 门槛。
- **合并后推荐**：分层混合架构——微观战斗"策略网络引导的 Expectimax 搜索（若状态拷贝达标）/ 掩码自回归策略网络（兜底）"双轨赛马；宏观决策改用"整局 MC 回报（DouZero 式）+ 卡组-地图双塔评估器（乙的对比学习方案）"，替代纯 TD 反传；KL 锚定保留但降级为"早期稳定器"并强制退火。

## 2. 逐题裁定

### 2.1 目标定义：甲对，乙错（事实裁定）

乙全文的 "A20" 不成立。甲的证据链（官方 Neowsletter：A0 胜率 16%、A10 约 17%；Untapped.gg/TheGamer：进阶 1–10，A10=双 Boss）为一手+双源交叉。**合并方案的目标统一为：STS2 A10，随机种子，单角色先行（Ironclad），胜率最大化。** 乙的"全职业整体通关胜率极大化"目标函数保留，但增加阶段化：A0 → A5 → A10 爬坡验收（甲 M4）。

### 2.2 非战斗决策的信用分配：两报共识，方案合并（设计裁定）

- 甲：纯 TD 反传梯度可能稀薄到不可用；备选 = potential-based 塑形 + DouZero 式整局 MC 回报。
- 乙：判定失效，替代 = 双塔对比评估器（卡组拓扑塔 × 地图风险塔，用 self-play 终局结果自监督训练，选牌 = 求生存期望增量最大的卡）。
- **合并方案（互不排斥，按序启用）**：
  1. **默认**：非战斗动作保留在策略网络中，但回报改为**整局 Deep Monte-Carlo**（战斗内可保留 TD/GAE，跨战斗用整局结算），这是 DouZero 在每局数百决策的牌类游戏中被验证的最短路径 [甲36]；
  2. **增强**：按乙的方案训练**卡组-地图双塔评估器**，作为 (a) 选牌时的贪心评估基线、(b) RL 的 value baseline / 辅助头。其编码器冷启动可用 HF 六数据集包的卡牌文本/多模态嵌入初始化（已核验：该包是卡牌元数据+Qwen3 嵌入，正好服务编码器预热，**不能**当 BC 轨迹数据用）；
  3. **消融**：M3 阶段三臂对照——纯 TD（spec 原案）vs 整局 MC vs 双塔评估器+MC，用固定种子集选胜者。
- 乙方案的一个未言明依赖，在此补上：双塔评估器需要"数百万局 self-play 终局日志"，而高质量 self-play 前提是战斗引擎已强——所以**必须先做微观（M1/M2）再收集 self-play 数据**，顺序不可颠倒。乙的验证路线图（微观先行）恰好隐含了这一点，予以确认。

### 2.3 微观战斗：接纳搜索路线，与原方案赛马（架构裁定）

乙最有价值的贡献是打破"神经网络直接出牌"的默认假设：
- **接纳**："微观计算脆弱性"论证成立——A10 双 Boss 容错极窄，算杀/出牌顺序的精度失误代价不成比例；STS 类战斗在"手牌+能量+意图+牌堆构成已知"下接近确定性数学规划，expectimax 只需对未知洗牌序做期望展开，分支可控。
- **修正乙的两处过度声明**：① "100% 确定性最优算杀"言过其实——抽牌序未知时是期望最优而非保证最优，且 STS2 新机制（亡灵缚者召唤、储君辉星）加大分支因子；② 乙假设"headless mod 能提供内存级状态深拷贝"——甲的取证显示**连 headless 跑通全局都无人公开验证过**，深拷贝是再往前两步的未验假设。乙自己也把"GC 停顿导致搜索瘫痪"列为最大风险，裁定：成立，故必须先测。
- **合并方案**：M1 阶段双轨赛马——
  - 轨道 A（乙案）：mod 内 C# 状态深拷贝 + 策略网络引导的深度 3–5 expectimax；
  - 轨道 B（甲案/spec 原案改进）：掩码自回归动作头 + BC 先验 + PPO；
  - **判据**（吸收乙的量化协议 + 甲的吞吐门）：50 个 Act 1 残局基准上，轨道 A 需满足单回合搜杀均耗时 < 200 ms、内存常数级无 GC 恶化、战后血量优于轨道 B；否则采用轨道 B。两轨共享同一套状态编码器与 BC 预训练，切换成本可控。

### 2.4 BC 与 KL 锚定：乙的批评成立，保留但降级（训练裁定）

- 乙指出的"KL 锚定陷阱"（把策略锁死在人类亚优范畴、阻碍超人类涌现）是甲未覆盖的真风险。甲原建议（KL 惩罚 + DQfD 演示回放）偏保守。
- 同时乙对 BC 的否定（"继承人类系统性偏见"）不能推翻 BC 本身：甲的取证显示 STS1 十年间**没有任何训练式 RL 公开成功**、启发式 AI 仅 5–10%、前沿 LLM 在 STS2 A0 全 0 胜 [甲25][甲21]——在这种策略复杂度下，"从零 RL"更不可能，BC 先验是必需品而非惯性。
- **合并方案**：BC 保留为初始化与演示回放池；KL 项保留但 (a) β 随训练退火至 0（明确"只护起飞、不锁航向"），(b) 训练中后期以"对 BC 的动作级 KL"仅作监控指标而非损失项，(c) 增加"探索预算"——每 N 个迭代注入无 KL 的纯 PPO 更新并用固定种子评估，若胜率不降则永久移除 KL。这样同时回应乙的"锚定"批评与甲的"崩塌"担忧。

### 2.5 单步马尔可夫与 Set-Transformer：两报无实质冲突，互补修补

- 乙批评"显式特征无法覆盖隐性时序状态（洗牌循环分布、伤害积压）"。甲论证过：牌堆构成显式编码后，剩余随机性属环境随机性而非信息缺失；乙举的"洗牌循环分布"恰是抽牌堆构成可算出的量。**裁定：架构维持单步 set 编码，但采纳乙的提醒，做一次"历史依赖效果全量审计"**（甲 §4.1 已列此项，升级为必做清单）：STS2 的遗物计数器、亡灵缚者墓地、储君铸造值、本回合已触发效果等逐一确认进状态。搜索轨道（2.3-A）天然绕开此问题（模拟器自己推进状态）。
- 地图拓扑问题（甲 §4.2）：乙的双塔"路线图谱塔"正好提供了载体——地图塔按邻接结构编码节点序列，比纯集合注意力更贴合。两案在此自然合流。

### 2.6 环境工程：甲的现实核查 + 乙的深拷贝门槛 = 合并 M0

两报的工程验证清单合并为 **M0 go/no-go 门（1–2 周）**，全部量化：

| # | 验证项 | 通过标准 | 来源 |
|---|---|---|---|
| 1 | STS2 当前版本 `--headless` 完整跑一局（含动画短路） | 可复现、无崩溃 | 甲 |
| 2 | 单实例吞吐（决策点/秒、局/秒） | ≥0.5 局/秒（讨论门槛） | 甲 |
| 3 | 多实例（8–64 进程）扩展比与内存 | 近线性、无互踩 | 甲 |
| 4 | **C# 状态深拷贝/回退延迟与 GC 行为** | 单步拷贝 <1 ms 量级、无累积停顿 | 乙 |
| 5 | seed 控制、存档隔离、版本锁定 | 可复现 | 甲 |
| 6 | 状态/动作接口复用 STS2MCP 或自研 mod | 合法动作列表完备（`is_playable`/`has_target` 式） | 甲+乙 |

#4 不过 → 搜索轨道出局，直接走轨道 B（神经网络出牌），这本身就是乙"退出条件"的正确执行。

### 2.7 数据计划：甲的现实核查为准，乙的素材归位

- BC 轨迹（逐决策）：无公开数据集。来源 = STS2Saves/AnalyticsTelemetry/spirescope 导出 + 高手合作录制（甲 §6）。HF 六数据集包**不提供轨迹**（本次已核验其内容为卡牌元数据与嵌入）。
- 乙的素材重新归位：HF 包 → 双塔评估器编码器初始化；MCPTheSpire → STS1 侧接口设计参照。
- self-play 日志（乙方案所需）：M2 产出的强战斗引擎 + 简单宏观规则即可开始滚动收集，作为 M3 输入。

## 3. 合并后的最终路线图

- **M0（1–2 周）环境门**：上表 6 项，特别是 headless 吞吐与状态深拷贝。产出：轨道 A/B 的取舍决定。
- **M1（2–3 周）BC 基线**：Ironclad 单角色；状态编码器 + 掩码自回归动作头；BC-only A0 胜率 vs 人类对照。
- **M2（4–8 周）微观战斗引擎**：轨道 A（expectimax 搜杀）或轨道 B（PPO+BC 先验）按 M0 裁决推进；战斗内 TD + 血量奖励 + 回合惩罚 + 硬超时；50 残局基准 + 固定种子战斗血损曲线验收。
- **M3（8+ 周）宏观与全场景**：整局 MC 回报为主线；双塔评估器作为 value baseline/选牌贪心基线并行训练；三臂消融（纯 TD / MC / 双塔+MC）；KL 退火实验。
- **M4：难度爬坡** A0 → A5 → A10，对照官方统计口径 [甲4]；每档固定种子评估集。
- **贯穿**：版本锁定 + 重训流水线（0.99→0.109 式平衡补丁是常态 [甲5][甲6]）；训练健康度仪表盘（KL、熵、送死率、每场景动作分布漂移、双塔评估器的 ROC-AUC——乙的 0.65 退出线保留为宏观模块的废除门槛）。

## 4. 遗留分歧（记录在案，留待实验裁决）

1. 乙认为端到端 RL"极度低效"应整体放弃战斗控制权；甲认为在搜索前提（深拷贝）未验证前不可押单边。→ 以 M0/M2 赛马结果裁决，本综合报告不预设结论。
2. 双塔评估器（乙）与"非战斗动作仍在策略网络中"（甲）的最终形态：可能收敛为"评估器出建议、策略网络出最终动作"的混合，也可能一者吞并另一者。→ M3 消融裁决。
3. A10 双 Boss 对终局信用分配的特殊难度：两报均未量化。→ M4 实测。
