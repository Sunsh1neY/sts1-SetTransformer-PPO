## 0. 术语与约定

- **回合** = 一个完整循环：玩家回合 + 敌人回合。回合数从 1 起。
- **实体** = 玩家或敌人。
- 状态效果以**剩余回合数**计（Vulnerable 2 = 还有 2 个递减周期）。
- 牌库为列表，**列表尾 = 牌库顶**。
- 手牌槽位 0-9，**按抽牌顺序分配**（v4 §4.3 关键约定：槽位分配必须确定，否则 replay 与 oracle 对拍失败）。
- 所有 `[未核实]` 项的共同出处：社区共识数值 / 记忆，未经 runlogger 日志或游戏内实测确认。

## 1. RNG 流（v4 §3 / Gate 1 第 3 条 / D14）

当前正式后端的主 RNG 为经 murmurHash3 初始化的 **xorshift128+**（`sts::Random`）；洗牌内部另建临时 Java 48 位 LCG（见 §1.1）。Python 教学实现 `sts/env/rng.py` 保留 4 条命名流，各自维护状态与消耗序列，不交叉取数：

| 流 | 对应游戏流 | 用途 |
|---|---|---|
| `shuffle` | `shuffleRng` | 洗牌、抽牌顺序 |
| `enemy_ai` | `aiRng` | 敌人行动选择、初始意图 |
| `enemy_roll` | `monsterHpRng` | 当前教学实现用于敌人 HP roll；其他 roll 的实际所属流以具体调用点为准 |
| `misc` | `miscRng` | 杂项随机；正式后端继承整局状态，Python 当前从 combat seed 新建，属于教学近似 |

- seed 只进环境，**不进观测**（v4 §3：防学到伪相关）。
- 每个随机操作的**消耗次数与顺序**是可复现性的一部分：同一 seed + 同一动作序列，流的消耗计数必须逐步相同（Gate 1 第 3 条按此断言）。
- `[未核实]`：固定首行动（如 Jaw Worm 的 Chomp）与各类 roll 是否消耗特定流，仍须按具体差异核验；现有可复现性断言不能证明调用序列与真实游戏完全一致。

### 1.1 当前后端的双层 RNG 与整局边界（D14，2026-09-05 修订）

依据本地 lightspeed 的 `include/game/Random.h`、`src/combat/Actions.cpp`、`src/combat/BattleContext.cpp` 及教学实现 `sts/env/rng.py`：

1. **主流**：`sts::Random` / `StsRandom` 使用 xorshift128+。`JavaRandom` 仅服务洗牌，不能把它的单独测试向量解释成所有战斗 RNG 都与游戏一致。
2. **洗牌**：先消耗 `shuffleRng.randomLong()`，以该值为种子新建临时 Java LCG，再执行 `Collections.shuffle` 对应的交换过程。主 `shuffle` 流每次洗牌消耗一次 long，临时 LCG 的取数另计。
3. **战斗初始化**：`combat_seed = run_seed + floor_num`。`aiRng`、`monsterHpRng`、`shuffleRng`、`cardRandomRng` 从同一初始状态复制为独立实例；楼层参与种子计算。
4. **整局继承**：`miscRng`、`potionRng` 从 `GameContext` 继承。仅有 run seed 和本场动作未必足以重建真实整局中某一场的全部状态，还需要楼层、初始化上下文与继承流状态。
5. **教学近似**：Python `CombatRNG(combat_seed)` 目前连 misc 也从传入种子新建，未实现完整 run 层继承；不能将 Python 与 C++ 的局部一致性推广到整局等价。

2026-09-03 关于“全部 RNG 均为 Java LCG”“五条流每层全部重置”“层数不进入流状态”的说法已被当前实现证据推翻。本次才在 D14 及变更记录中正式登记，早先代码已改不代表早先文档也已同步。

此节描述已查阅的后端与教学实现；未覆盖的真实游戏随机调用路径继续标记 `[未核实]`，不作为当前训练的额外全机制对拍任务。

## 2. 战斗初始化 `reset(seed)`

以下为 Python 教学切片的初始化步骤；正式 C++ 后端复用 `BattleContext::init`，其整局流边界按 §1.1：

1. 传入的是 `combat_seed`；若来源是整局日志，先按 `run_seed + floor_num` 派生。教学实现的四条流从 `StsRandom(combat_seed)` 初始化，misc 的近似边界见 §1.1。
2. 构建牌库（固定构建顺序）：Strike ×5 → Defend ×4 → Bash ×1。
3. 按 §1.1 的双层 RNG 洗牌一次。
4. 生成敌人：按遭遇配置的顺序实例化；每个敌人 HP 在其区间内用 `enemy_roll` 流依序 roll；Louse 的每场咬伤定值同时 roll 并存于实例。
5. 敌人初始意图：按生成顺序用 `enemy_ai` 流决定（Jaw Worm 首回合固定 Chomp，见 §7）。
6. 玩家：HP 80、block 0、能量 3、回合数 = 1。
7. 抽 5 张（§6），手牌槽位 0-4 按抽牌顺序。
8. 状态 = 玩家行动阶段。

## 3. 回合结构（结算主循环，按编号顺序执行）

### P — 玩家回合开始

1. 玩家 block = 0。
2. 能量 = 3；回合数 += 1。
3. 回合开始触发（最小切片：无）。
4. 抽 5 张（§6）。
5. 玩家 debuff **不在**回合开始递减（递减时机见 S2）。

### A — 玩家行动（循环，每次一个动作）

1. 执行一个合法动作：`play_card(slot, target)` 或 `end_turn`。
2. 卡牌结算（§5）。
3. 敌人全灭检查（§X1）→ 全灭则**立即**胜利，本回合后续一切不执行。

### T — `end_turn` 触发

1. 手牌按**当前手牌列表逆序（高槽位到低槽位）**依次置入弃牌堆；与当前 C++ `discardAtEndOfTurnHelper` 和 Python 教学实现一致。
2. 玩家 debuff 时长各 -1（Weak）。
3. 进入敌人回合（N）。

### N — 敌人回合（按生成顺序逐个敌人）

对每个**存活**敌人依次：

1. 其 block = 0。
2. 执行其意图（§7）。
3. 其回合结束触发（Cultist：刚获得 Ritual 时跳过首次力量增长，此后回合末力量 +3，见 §7）。
4. 玩家 HP ≤ 0 → **立即**判负，后续敌人不再行动（§X2）。

全体敌人行动完毕后：

5. 所有存活敌人 debuff 时长各 -1（Vulnerable / Weak）。
6. 回到 P（新玩家回合开始）。

> **裁定**：debuff 递减时机 = 受影响方回合结束时（玩家在 T2，敌人在 N5）。此约定与"Vulnerable 2 给你两轮 ×1.5 攻击窗口"的公认行为一致（单测 T07/T08）。在最小切片中，"回合末递减"与"回合初递减"两种约定**不可区分**（无中途上 debuff 的来源）；第 3 周对拍若日志能区分，以日志为准修订本条。
>
> **裁定**：敌人 block 清零在**各自回合开始**（N1），非全局统一清零——与 STS1 逐实体回合模型一致；敌人回合内获得的 block 存续到你的回合结束。

### X — 战斗结束

- **X1 胜**：所有敌人 HP ≤ 0，任意时刻判定，立即生效。
- **X2 负**：玩家 HP ≤ 0，任意时刻判定，立即生效。
- **X3 硬超时**：回合数 > 50 判负（config `max_turns`，默认 50；v4 §3：防死锁轨迹污染数据）。它属于任务终局：C++ 接口返回 `terminated=true`、`truncated=false`、`info.timeout=1`，奖励 0，训练不自举；与训练批次截断区分（D20）。
- **X4** 结束即冻结全部状态；奖励计算按 v4 §4.4，不在本文档范围。

## 4. 伤害计算（攻击方 → 目标）

按序执行：

1. `base` = 卡面基础伤害（玩家）或意图伤害 + 当前力量（敌人，见 §7）。
2. 攻击方有 Strength → `base += Strength`（负亦然）。**先加力量**（v4 §5.3 裁定）。
3. 目标有 Vulnerable → `base = floor(base × 1.5)`。
4. 攻击方有 Weak → `base = floor(base × 0.75)`。
5. `base < 0` → 取 0。
6. 结算到目标：**先扣 block，余量扣 HP**。
7. HP ≤ 0 → 死亡（即时；其未执行的意图作废）。

> **裁定**：每步乘法后立即 floor；Vulnerable 先于 Weak 计算。
> **对拍注**：Vuln+Weak 同时生效才可区分两种乘法顺序，而最小切片中**不存在**两者同时作用于同一伤害的情形（玩家无力量来源、敌人无 Weak 来源）——故本裁定在第一档内不可被日志证伪；第二档（Inflame 等）入库前必须完成对拍校准。手算单测按本裁定执行（T06）。
> **2026-09-03 社区来源核实**：力量最先加入计算（Fandom wiki Strength 页：strength "added to the calculation first" before Vulnerable/Weak 等修饰）✓；易伤伤害向下取整（Fandom wiki Vulnerable 页："Vulnerable damage is rounded down"）✓。⚠️ 乘法先后出现**矛盾证据**：社区流传公式写作 (base+str) ×0.75(weak) ×1.5(vuln)，即 Weak 在前，与本裁定相反。处置：第二档入库前用反编译源码定点仲裁（decisions.md U7），不盲猜、不靠对拍试错。

## 5. 卡牌结算（最小切片卡表）

| 卡 | 费用 | 效果 |
|---|---|---|
| Strike | 1 | 对单体目标造成 6 点攻击伤害 |
| Defend | 1 | 获得 5 点 block |
| Bash | 2 | 对单体目标造成 8 点攻击伤害，**然后**施加 Vulnerable 2 |

结算顺序：

1. 扣除能量（先扣费，后结算）。
2. 卡牌离开手牌 → 结算效果 → 置入弃牌堆。
3. 攻击卡执行 §4 流程。
4. **Bash 裁定**：先伤害、后施加 Vulnerable——Bash 自身伤害只吃到目标**已有**的 Vulnerable，不吃自己上的（T16/T17）。`[未核实]` 以对拍为准。
5. 无目标卡（Defend）在动作编码中目标槽固定 0。

`[未核实]`：以上卡面数值为社区共识值，第 3 周对拍时逐一确认。

## 6. 抽牌 / 洗牌

1. 抽 1 张 = 弹出牌库顶（列表尾）。
2. 抽牌时牌库空 → **先**把弃牌堆整体洗入牌库（§1.1 的双层洗牌一次），再抽。
3. 牌库、弃牌堆皆空 → 本次抽牌放弃（手牌可为 0，此时唯一合法动作 = `end_turn`）。
4. 手牌已满 10 → 抽牌失败，牌留在牌库顶。`[未核实]` STS1 规则；最小切片抽 5 不会触发，防御性实现按此条。
5. 洗牌 RNG 消耗次数计入可复现性断言（T12）。

## 7. 敌人规格（最小切片）

> 通用：敌人攻击伤害 = 意图基础值 + 当前 Strength（§4 第 2 步）。敌人可拥有 block（Thrash/Bellow 来源，N1 清零）。

### Jaw Worm（单敌遭遇）

- HP：40-44 区间 roll。`[未核实]`
- 行动表：
  - **Chomp**：攻击 11。`[未核实]`（A2+ 为 12，本项目固定 A0 数值）
  - **Thrash**：攻击 7，自身获得 block 5。
  - **Bellow**：自身力量 +3，获得 block 6。
- AI：首回合**固定 Chomp**；此后行动概率 45% Thrash / 30% Bellow / 25% Chomp，连用同一行动的约束规则 `[未核实]` —— 以日志反推为准（第 3 周任务）。

### Cultist（单敌遭遇）

- HP：48-54 区间 roll。`[未核实]`
- 行动：第 1 回合 **Incantation** 赋予自身 Ritual；Ritual **跳过刚施加时的首次回合末增长**，此后回合末力量 +3。之后每回合 **Dark Strike** 基础攻击 6。
- 推演锚点：敌 T1 无攻击且回合末力量仍为 0 → 敌 T2 Dark Strike 6、回合末力量 3 → 敌 T3 Dark Strike 9（T09/T10）。当前后端依据为 `Monster::applyEndOfRoundPowers` 的 `wasJustApplied<RITUAL>` 分支；不据此扩充其他未核实敌人数值。

### Louse ×2（多敌遭遇；红/绿）

- HP：红 10-15、绿 11-17 区间 roll。`[未核实]`
- **Bite**：攻击，伤害值**每场战斗开局 roll 一次**（5-7），存于实例，全程不变。`[未核实]`
- **Spit Web**（绿）：玩家 Weak +2。
- **Grow**（红）：自身力量 +3。
- **Curl Up**：首次受到攻击伤害时获得 block 3-7（每场一次）。`[未核实]`
- 各体行动概率与首行动 `[未核实]`，以日志反推为准。
- 生成顺序 = 动作目标索引顺序（0 = 第一只）。

## 8. 动作空间与合法性（v4 §4.3）

1. 动作总数 `A = max_hand × max_target + 1`，末位 = `end_turn`。配置默认 `max_hand = 10`，`max_target = 3`（第一档实际敌人 ≤ 2；中等档预留 3）。
2. 索引解码：`i < A-1` → `slot = i // max_target`，`target = i % max_target`；`i = A-1` → `end_turn`。
3. 动作合法 ⟺ 槽位有牌 **且** 当前能量 ≥ 卡费 **且** 目标合法（攻击卡：目标存活；无目标卡：target = 0）。
4. 环境直接输出合法动作列表与 mask，模型不猜（v4 §3）。
5. 环境拒绝一切非法动作（Gate 1 第 4 条：随机策略非法动作率恒 0）。
